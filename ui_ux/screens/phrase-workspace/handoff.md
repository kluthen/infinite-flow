# Phrase Workspace Handoff

## Layout Tree

```text
layout-app
  layout-header
    brand-mark
    header-actions
      context-group
        score-context
          meter-badge
          tempo-readout
        theme-control segmented-control (system, light, dark)
      btn btn-primary btn-lg (phrase action)
  layout-workspace
    score-panel
      score-toolbar
        score-context
        generation-status
      inline-alert alert-error (generation-failure banner; sibling of score-toolbar, before staff-viewport; present whenever a generation error is retained -- the two generation-error states, and also, unchanged, alongside a later co-active notation error -- see States)
      staff-viewport
        staff-frame
          staff-empty, staff-loading, staff-error, staff-ready, or staff-content
            chord-symbol
            measure-slot
    control-section
      control-section-title
      control-section-copy
      control-summary
      control-group-row
        control-group (foundation)
          field-group (tempo)
          field-group (written key)
          field-group (collection)
          field-group (instrument profile)
            segmented-control
            profile-range-summary
          field-group (musical profile preset)
            segmented-control
            preset-status
          field-group (harmonic motion)
          field-group (tension)
        control-group (rhythm)
          field-group (note density)
          field-group (rhythmic variety)
          field-group (syncopation)
          field-group (silence density)
          inline-alert alert-notice (unsupported-rhythm notice; persistent live region, empty and visually absent otherwise)
        control-group (melodic shape)

          field-group (register)
          field-group (leapiness)
        control-group (character)
          character-static
            field-group (arpeggio chaos)
```

## Components and Content

- The root uses `layout-app`; the header uses `layout-header`; the body uses `layout-workspace`.
- `score-panel` uses `score-panel`; its header uses `score-toolbar`. The visible title is `Four-measure phrase`.
- `staff-frame` renders one `staff-content` unit with exactly four `measure-slot` elements and a semantic SVG music score.
- `chord-symbol` uses `--font-music` or `--font-ui` only when the notation engine cannot engrave chord symbols; it is never placed independently from the harmonic event it labels.
- Every single-select `segmented-control` has `role="radiogroup"` and an accessible group label; each `segment` has `role="radio"` and `aria-checked="true"` or `"false"`. Exactly one segment is checked when a value is active, and the checked segment also receives `is-selected` for its visual state. The one sanctioned exception is the custom musical-preset state (see below), where the musical profile preset `radiogroup` has no checked segment at all — ARIA permits a `radiogroup` with no checked radio, and this design set never adds an unselectable "Custom" radio to stand in for it. Each group uses a roving tab stop: the checked segment is the only `tabindex="0"` option, with all others at `tabindex="-1"`; when the custom musical-preset state has no checked segment, its first option (`Neutral`) is the tab stop. Left and Up move to the prior option, Right and Down move to the next option, and each move selects and focuses its destination.
- There is no notation-display selector and no Concert override in the header or anywhere else: the score always renders in the currently selected instrument profile's own written pitch (see Notation Contract). The header carries only `meter-badge`, `tempo-readout`, and `theme-control` alongside the phrase action.
- `theme-control segmented-control` uses `System`, `Light`, and `Dark`. `System` follows the operating-system preference; `Light` and `Dark` set a manual presentation override. This selection changes presentation only: it cannot change a phrase, any control value, generation request, seed, selected profile, or result.
- The primary action is `btn btn-primary btn-lg`: `Generate phrase` before a result, otherwise `Regenerate phrase`.
- `generation-status` is a persistent, visually hidden `role="status"` region with `aria-live="polite"` and `aria-atomic="true"`. It announces `Generating phrase`, `Phrase ready`, and `Generation failed. Try again.` after the corresponding state has changed; it never announces control navigation, preset changes, or notation/theme display changes.
- `notation-status` is a separate, persistent, visually hidden `role="status"` region with `aria-live="polite"` and `aria-atomic="true"`, independent of `generation-status`. It announces `Notation error. Try again.` whenever a notation error becomes set, regardless of source — including a fresh generation's own engraving step failing right after a successful generate, regenerate, retry, or profile-switch regeneration (the most common way the standalone **Notation error** state is first reached), a clicked `Retry notation`, or an out-of-band redraw failure (a viewport resize or breakpoint crossing) — all announce identically, in both the standalone **Notation error** state and **Notation error over a retained generation failure**. It does not announce when the notation error clears; recovery stays silent, and `generation-status`'s own scope (no control-navigation, preset, or notation/theme-display announcements) is unchanged by this region.
- `staff-frame`'s state class additionally distinguishes, while idle, a retained score that has actually been successfully engraved since it was last set or last blanked by an error from one that has not: only the former renders `staff-ready`. This distinction applies only once the workspace is idle — while a generation or notation attempt is in flight, `staff-frame` is unaffected by it, so a fresh generation's own engraving step never flashes this state; the previous content keeps showing throughout, per the existing **Loading** state's stability guarantee. A retained score that has not been re-engraved since a notation error blanked it and is now idle — for example, when a later Regenerate, Retry generation, or profile-switch regeneration clears the notation error as a side effect of starting without ever repairing the blanked staff (see States, "Notation error" and "Notation error over a retained generation failure") — instead renders `staff-error` with no local message, relying on the generation-failure banner already on screen for the explanation rather than misrepresenting the blank staff as ready.
- `control-summary` is a single line of muted, small static text in `control-section`, after `control-section-title` and `control-section-copy` and before `control-group-row`. It is plain text: not a live region, never announced, and carries no `aria-hidden`. Its copy is `{written key label} {collection label} · {musical profile or custom label} · {tension arc label} · {leapiness label}`, with a plain space between the written-key and collection labels and ` · ` (U+00B7 surrounded by spaces) between the remaining three segments. The written-key label matches the label the written-key control itself shows (e.g. `C-sharp/D-flat`), in the currently selected instrument profile's written pitch. The musical-profile segment reads `Neutral` or `Jazz` when a preset is currently selected, or `Custom ({grammar} grammar)` during the custom state, using the same retained-grammar word `preset-status` shows. It recomputes on every change to written key, collection, musical profile preset or custom state, tension, or leapiness, and is independent of the selected instrument profile's own written pitch (switching profile never changes what `control-summary` says, only what the score shows). Examples: default load `C Ionian · Neutral · Lift · Shaped`; Jazz preset selected `C Ionian · Jazz · Lift · Shaped`; custom state after a Neutral edit `C Ionian · Custom (Neutral grammar) · Lift · Shaped`.
- The below-score control section groups `field-group` instances: foundation (tempo, written key, collection, instrument profile, musical profile preset, harmonic motion, tension); rhythm (note density, rhythmic variety, syncopation, silence density); melodic shape (contour, register, leapiness); character (arpeggio chaos).
- Instrument profile uses `segmented-control` for C MIDI keyboard, B-flat tenor saxophone (default selection), and E-flat alto saxophone. The selected `profile-range-summary` states the profile's active range and Low, Middle, and High whole-phrase windows.
- The written-key control ("Written key," a `segmented-control` of all twelve pitch classes) and the collection control read and write the tonal context in the currently selected instrument profile's own written pitch — not concert pitch. Selecting a different instrument profile never changes the written-key or collection selection; only what the score sounds and validates against changes. The first-load written key is C, and the first-load collection is Ionian. Every pitch class is selectable; displayed notation uses the written selection's lowest-accidental spelling, using sharps on a tie. Tempo initially displays 90 BPM and moves by its defined product step within its defined product bounds.
- The collection menu exposes major, minor, Ionian, Dorian, Phrygian, Lydian, Mixolydian, Aeolian, and Locrian.
- The neutral preset selects static harmonic motion, quarter-note density, `Slightly varied` rhythmic variety, straight syncopation, sparse rests, arch contour, and middle register. The jazz preset selects gentle diatonic harmonic motion, eighth-note density, `Slightly varied` rhythmic variety, occasional offbeats, conversational space, wandering contour, and `Varying` register.
- After the player manually changes any preset-controlled value, clear the preset selection and show `preset-status is-custom` as `Custom configuration - Neutral grammar retained` or `Custom configuration - Jazz grammar retained`, according to the preset last applied. The visible status is a polite status region and states that choosing `Neutral` or `Jazz` replaces all seven preset-controlled values. Selecting either preset restores its complete bundle, replaces the custom values, selects that preset, and announces the applied preset through the same status region.
- **Rhythmic variety** sits in the rhythm `control-group`, immediately after note density, as a `segmented-control` with three options: `Strict`, `Slightly varied` (default), and `Heavily varied`. It is preset-controlled, the seventh preset-controlled field: both the neutral and jazz presets set `Slightly varied`, and a manual edit after a preset puts the musical-profile-preset `radiogroup` into the same custom state a manual edit to any other preset-controlled field does (see States, "Preset customization"). The exact value set and weighting per level and note density are fixed by a separate rhythm-grammar feasibility review before implementation; this handoff defines only the control's label, shape, position, and preset participation, not the musical values it produces.
- Note density offers exactly three options: `Quarter`, `Eighth`, and `Sixteenth`. There is no `Mixed` option; `Heavily varied` rhythmic variety is how a phrase gets a mixed feel.
- Arpeggio chaos exposes `Predictable`, `Varied`, and `Chaotic`, ordering chord-tone candidates relative to the previous pitch: `Predictable` prefers the nearest chord tone, `Chaotic` prefers the farthest chord tone, and `Varied` leaves the chord-tone order to the seeded tie-break. It never bypasses profile, contour, range, or resolution constraints.
- Contour options, in order: `Rising`, `Falling`, `Arch`, `Wandering`.
- The `character` control group holds only Arpeggio chaos. Its `character-static` wrapper is always visible and never collapsible or progressively disclosed; it exists solely for the visual separator (border and spacing) above the group's single field, not for a disclosure interaction.
- Every discrete setting uses `segmented-control`; only tempo uses `input-stepper`. Every control has a `field-label`, selected-value feedback, and an accessible description.
- The rhythm `control-group` ends with a single `inline-alert alert-notice`, `role="status"` with `aria-live="polite"` and `aria-atomic="true"`, reporting when the current rhythmic variety, note density, syncopation, and silence density combination cannot form a four-bar phrase, together with a nearer-supported-combination suggestion. Rhythmic variety participates in this check alongside the other three controls: changing variety alone, with nothing else touched, can newly block or newly unblock the combination. This region is persistent in the accessibility tree at all times, with empty text and no visible alert styling when the combination is supported, so a screen reader is already tracking it before it ever has something to announce; visibility must never be toggled with a mechanism that removes the region from the accessibility tree (e.g. `display: none`) while blocked could become true. See States, "Unsupported rhythm combination."
- The `inline-alert alert-error` generation-failure banner (a sibling of `score-toolbar`, not nested inside it — see Layout Tree) shows exactly one calm, plain-language string, never a raw failure code and never the word "Generation failed" concatenated with the underlying error's own message. Selection: when the failure is a typed generation failure carrying one of the six documented failure codes, show that code's string below; for every other failure (a generation-Worker crash, a Worker transport failure, or any other unrecognized error), show the shared fallback string. This banner is independent of the `generation-status` live region, which stays the fixed announcement "Generation failed. Try again." in every case below.
  - `no_legal_harmony_plan`: "This combination of written key, collection, harmonic motion, tension, and musical profile can't produce a phrase. Try a different written key, collection, harmonic motion, tension, or profile."
  - `no_legal_rhythm_plan`: "This combination of note density, syncopation, and silence can't form a four-bar phrase. Try a different note density, syncopation, or silence setting."
  - `no_legal_pitch_plan`: "This combination of settings can't produce a phrase. Try a different register, contour, or rhythm setting."
  - `no_eligible_register_window`: "None of this instrument's register windows fit the current settings while register is set to Varying. Try a different contour."
  - `search_limit_exceeded`: "This phrase search hit its work limit before finding a result. That doesn't prove this combination is impossible. Trying again may find a result, or try different settings."
  - `result_validation_failed`: "Something went wrong while building this phrase. This wasn't caused by your settings."
  - Any other failure (Worker crash, transport failure, or unrecognized error): "Generation couldn't complete. Try again."
- `Retry generation` (the workspace-header action's label in both generation-error states) builds a new generation request from the current control values and selected instrument profile, with a fresh seed and request identity — the same construction as `Regenerate phrase` — rather than replaying the failed request unchanged. If the player edits a control after the failure and before pressing it, the retried request reflects that edit; for the four typed failure codes whose alert string names specific settings (harmony, rhythm, pitch, register window), this is how that hint takes effect. `search_limit_exceeded`'s hint to "try different settings" works the same way if the player edits a control, but its "trying again" half can also succeed from the fresh seed alone with no control changed. `Retry notation` (the notation-error state's action) is unrelated: it re-engraves the already-generated phrase's stored request and never builds a new generation request.
- The `alert-error` banner is not re-validated against ordinary control edits: once shown, its content and the `Retry generation` label stay exactly as they are through any number of field-group changes, and change only when the next generation attempt starts — the banner leaves while that attempt is in flight, the workspace moves to Ready on success, and another failure shows the banner again with the new attempt's failure string. The one exception is an instrument-profile switch made while the current rhythm combination (rhythmic variety, note density, syncopation, silence density) is already unsupported (see Notation Contract; States, "Unsupported rhythm combination"): that switch clears the retained phrase and returns the workspace to **Empty** without running a generation request, regardless of whether the new profile's range would otherwise have fit it — which leaves the "Generation error" state — and its `alert-error` banner and `Retry generation` label — behind in favor of the empty-state `Generate phrase` action and the unsupported-rhythm `inline-alert alert-notice`.
- The generation-failure `alert-error` banner's presence condition is independent of a notation error: it stays visible, unchanged, if a notation redraw on the retained score fails while the banner is already showing (see States, "Notation error over a retained generation failure"). While that holds, the workspace-header action reads `Retry notation`, not `Retry generation`, even though the banner is still on screen: only one workspace-header action exists at a time, and a co-active notation error always takes it. The banner becomes actionable again, unchanged, as soon as the notation error clears.

## Notation Contract

- `staff-content` renders in the currently selected instrument profile's own written pitch, transposed from concert-pitch events by that profile's own fixed chromatic and diatonic transposition, always in treble G2 clef. There is no separate notation-display selector and no Concert override: C MIDI keyboard is a unison transposition, B-flat tenor saxophone a major ninth, E-flat alto saxophone a major sixth. The transposition transforms written notes, key, written-key label, chord roots, and the slash bass, if a chord symbol ever carries one (current harmony produces none), while preserving chord quality, alterations, extensions, additions, and omissions, and never alters the concert-pitch events themselves.
- The key signature is spelled from the player's written-key selection directly, not re-derived from the concert tonal center.
- The score includes the applicable clef, key signature, 4/4 signature, rhythmic glyphs, rests, beams, ties, accidentals, barlines, and chord symbols. Chord symbols — root and, if a chord symbol ever carries one (current harmony produces none), slash bass — follow the same written-pitch transposition as every other written element above.
- `measure-slot` boundaries represent real measure extents from engraving layout. They do not invent beat positions or vertically place pitch glyphs in CSS.
- The layout refuses to show a phrase until all four measure durations validate. A phrase must not be cut off, horizontally scrolled, shrunk below its legibility floor (the minimum engraving scale at which the score stays readable), or split into more than two staff systems at supported breakpoints; the score's height follows its content.
- At `bp-tablet-landscape` and above, the score always engraves as exactly one staff system holding all four measures; if it cannot fit at the legibility floor, the notation-error state applies (see States). Below `bp-tablet-landscape`, the score first attempts one staff system with all four measures; when that does not fit at the legibility floor, it engraves as two staff systems of two measures each within the same staff area — bars 1-2 on the first system, bars 3-4 on the second — with clef and key signature repeated on the second system and the 4/4 time signature shown only on the first system. All four `measure-slot` regions stay visibly equal in width in both the one-system and two-system layouts, and the two systems' measure columns stay aligned with each other. If two systems also cannot fit at the legibility floor, the notation-error state applies.
- On profile selection while a phrase exists, never validate the old phrase against the new active range and never retain or redraw it: keep the written key, collection, and every other control, take a fresh seed, and regenerate the complete phrase as a replacement under the new profile. The one exception is a rhythm-control combination (rhythmic variety, note density, syncopation, silence density) that is already unsupported at the moment of the switch: the switch still applies, but the phrase clears and the workspace returns to the empty state instead of regenerating — see States, "Unsupported rhythm combination." With no phrase shown yet, a profile switch only changes the selected profile; nothing generates.

## Responsive Behavior

- At `bp-mobile-landscape`, use one full-width score row above a stacked `control-section`. `layout-header` wraps and reflows `brand-mark`, `theme-control segmented-control`, and the primary action through the canonical header classes; no header content overflows. Each `field-group` gives its `segmented-control` the available inline size, and its segments wrap within it; including all twelve written-key choices, no segmented control overflows. The score first attempts a single four-measure staff system; when that does not fit at the legibility floor, it falls back to the two-system layout defined in the Notation Contract, with equal-width measure regions and aligned columns across both systems. First load selects the B-flat tenor saxophone instrument profile.
- At `bp-tablet-landscape`, use one full-width score row above a `control-group-row` that wraps as needed. The controls scroll with the page; `staff-viewport` uses its full available inline size.
- At `bp-desktop`, use the same vertical structure. Orient control groups horizontally across the page and give `staff-viewport` its maximum available inline space; do not add a side rail or third content column.
- Below `bp-desktop`, when the viewport is portrait, use `orientation-notice` instead of an interactive score layout. At `bp-desktop` and above, do not apply the portrait guard; retain the full-width `staff-viewport` when width is sufficient.
- All visual styling and responsive dimensions use the canonical tokens and component classes in `src/styles/theme.css` and `src/styles/components.css`; this handoff declares no independent visual values.

## States

- **Empty:** `staff-frame staff-empty` shows a short instruction without fake notes or placeholder music. The workspace-header `btn btn-primary btn-lg` is the sole `Generate phrase` action.
- **Loading:** `staff-frame staff-loading` retains the staff frame and status text; only the phrase-generation `btn` is disabled with `is-loading`. Every configuration control receives `is-readonly` and `aria-readonly="true"`, preserving its selected value without accepting changes until the request completes. Read-only controls keep their label, value, and selected-segment colors exactly as the active state (never dimmed) and are marked locked only by the read-only ring; they remain focusable context, but their pointer and keyboard handlers suppress value changes, including radio arrow-key navigation. The previous valid `staff-content` remains visible during regeneration. `generation-status` announces `Generating phrase`.
- **Ready:** `staff-frame staff-ready` presents all four engraved measures and chord symbols. `staff-content` uses the defined fade replacement policy.
- **Initial generation error:** `staff-frame staff-empty` remains in place with its instruction, and the `inline-alert alert-error` generation-failure banner (a sibling of `score-toolbar` — see Layout Tree) appears with the content defined above; the sole workspace-header generation action changes label to `Retry generation`, which builds a fresh request from the current controls and profile (see Components and Content). No score or placeholder music is shown.
- **Generation error:** the `inline-alert alert-error` generation-failure banner (a sibling of `score-toolbar` — see Layout Tree) appears with the content defined above; retain the prior valid score, and the sole workspace-header generation action changes label to `Retry generation`, which builds a fresh request from the current controls and profile (see Components and Content).
- **Notation error:** `staff-frame staff-error` replaces only the affected score content with an error message; retain the phrase request context, and the sole workspace-header generation action changes label to `Retry notation`. Reaching this state, however it is reached, announces `Notation error. Try again.` through `notation-status` (see Components and Content). Controls stay fully editable while this state holds, including instrument profile and rhythm: switching instrument profile always regenerates the phrase immediately — clearing this notation error as a side effect of starting the new attempt — when the current rhythm combination is supported, or clears the phrase entirely and returns to **Empty** with the unsupported-rhythm alert showing when it is not (see States, "Unsupported rhythm combination"); either way it leaves no notation error behind. If the regenerated attempt itself then fails, the result is not a clean return to **Generation error**: the staff stays exactly as blank as it was under the notation error, but `staff-frame` correctly falls back to `staff-error` with no local message rather than misclassifying as `staff-ready` (see Components and Content), now beneath a fresh generation-failure banner with a working `Retry generation`. The staff can also recover through a clicked `Retry notation` that succeeds, or through an out-of-band redraw (a resize or breakpoint crossing) that succeeds once whatever caused the failure no longer applies; if an out-of-band redraw instead fails again, the state stays exactly this plain **Notation error** — there is no generation-failure banner on record to fall back to.
- **Notation error over a retained generation failure:** Reachable only from **Generation error** (never from **Initial generation error**, which has no retained phrase for a redraw to fail against): an out-of-band redraw of the score retained after a generation failure — a viewport resize or breakpoint crossing — itself fails. With no notation-display selector and no profile-switch retain path, nothing else asks an idle retained score to redraw, so this out-of-band redraw is the only trigger. The generation-failure `inline-alert alert-error` banner stays visible, unchanged, exactly as in **Generation error**; `staff-frame` simultaneously switches to `staff-error`, replacing only the affected score content with "Notation error: …" — the staff area shows no score, not the stale retained phrase underneath — exactly as in **Notation error**. The sole workspace-header action reads `Retry notation`, not `Retry generation` — a co-active notation error always takes the one available action, even while the generation-failure banner remains on screen. Controls stay fully editable while this state simply sits on screen, becoming read-only only for the brief window a clicked `Retry notation` is actually redrawing, using the same mechanic already defined under **Loading** (the below-score control panel and the header's phrase action). The theme control stays interactive throughout, exactly as in every other state, and the out-of-band failure itself never makes controls read-only. No focus moves in any case. Reaching or re-entering this state announces `Notation error. Try again.` through `notation-status` (see Components and Content), independent of and in addition to whatever `generation-status` is doing; `generation-status` itself stays silent here, since an out-of-band redraw never changes its driving `operation` value. This state resolves one of three ways: (a) a clicked `Retry notation` or an out-of-band recovery succeeds, clearing only the notation error and restoring `Retry generation` with the banner unchanged beneath it, per the persistence rule above — the banner itself changes only on the next generation attempt; (b) an instrument-profile switch, always available from this state, clears both errors immediately as it starts a fresh generation attempt when the current rhythm combination is supported — landing in **Ready** on success, or, if that fresh attempt fails in turn, in a fresh **Generation error** with the staff correctly falling back to `staff-error` rather than the misleading `staff-ready` (see Components and Content); or (c) that same switch instead clears the phrase entirely and returns to **Empty** with the unsupported-rhythm alert showing, when the current rhythm combination is already unsupported, per the existing profile-switch-to-Empty exception, leaving neither error behind.
- **Theme override:** `theme-control` marks `System`, `Light`, or `Dark` as selected. It immediately updates semantic presentation tokens without loading or redrawing the score and without changing phrase or request data.
- **Preset customization:** A manual edit to a preset-controlled field clears the selected preset (the musical-profile-preset `radiogroup` has no checked segment; its first option remains the roving tab stop) and updates `preset-status is-custom` to the visible retained grammar, `Neutral` or `Jazz`; `control-summary` updates its musical-profile segment to `Custom ({grammar} grammar)` in the same moment. Selecting either preset restores and announces that preset's complete bundle, and `control-summary` returns to showing `Neutral` or `Jazz`.
- **Unsupported rhythm combination:** When the current rhythmic variety, note density, syncopation, and silence density combination cannot form a four-bar phrase, `inline-alert alert-notice` becomes visible at the end of the rhythm `control-group` with its message and suggestion, and every phrase action except `Retry notation` becomes disabled (`Retry notation` replays an already-generated phrase's stored request and does not depend on the current rhythm combination). Rhythm and every other control stay fully editable, not read-only, while blocked; the disabled reach is limited to the phrase action. Leaving the unsupported combination re-enables the phrase action and empties, but does not remove, the live region. If a phrase is currently shown, a profile switch made while this alert is showing always clears that phrase and returns the workspace to **Empty** instead of regenerating — the new profile still applies, and this `inline-alert alert-notice` stays visible, still explaining why `Generate phrase` is blocked; no generation request runs. If no phrase is shown, the switch only changes the selected profile and this alert stays exactly as it was.
- **Offline:** Keep all required generation, notation, controls, and the current phrase available. Do not show an offline blocker because required behavior is browser-local.
