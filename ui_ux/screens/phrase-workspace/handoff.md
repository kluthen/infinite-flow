## Components and Content

- The root uses `layout-app`; the header uses `layout-header`; the body uses `layout-workspace`.
- `score-panel` uses `score-panel`; its header uses `score-toolbar`. The visible title is `Four-measure phrase`.
- **[v2 changed]** `staff-frame` holds the two staff system positions in every state (see Notation Contract). Each position that shows notes holds one `staff-content` unit, its own engraving as a semantic SVG music score, with its own `measure-slot` elements: four in the one-system layout, two in the split layout. At idle in the one-system layout, the top position holds phrase 1 and the bottom one is reserved and empty; in the split layout, phrase 1 is two units, bars 1–2 on top and bars 3–4 below, both drawn at the phrase's one scale. The fade and the refill apply per unit, and each unit carries its phrase's engraving scale, so a session start redraws nothing and each system can fade on its own.
- `chord-symbol` uses `--font-music` or `--font-ui` only when the notation engine cannot engrave chord symbols; it is never placed independently from the harmonic event it labels.
- Every single-select `segmented-control` has `role="radiogroup"` and an accessible group label; each `segment` has `role="radio"` and `aria-checked="true"` or `"false"`. Exactly one segment is checked when a value is active, and the checked segment also receives `is-selected` for its visual state. The one sanctioned exception is the custom musical-preset state (see below), where the musical profile preset `radiogroup` has no checked segment at all — ARIA permits a `radiogroup` with no checked radio, and this design set never adds an unselectable "Custom" radio to stand in for it. Each group uses a roving tab stop: the checked segment is the only `tabindex="0"` option, with all others at `tabindex="-1"`; when the custom musical-preset state has no checked segment, its first option (`Neutral`) is the tab stop. Left and Up move to the prior option, Right and Down move to the next option, and each move selects and focuses its destination.
- **[v2 changed]** There is no notation-display selector and no Concert override in the header or anywhere else: the score always renders in the currently selected instrument profile's own written pitch (see Notation Contract). The header carries `controller-status`, `meter-badge`, `tempo-readout`, and `theme-control`, then the phrase action and the session action.
- **[v2 new]** `controller-status`, in `context-group` before `theme-control`, is the only entry point into `flows/controller-connection/` (`screens/controller-connection/`). It is always a `button` composed as `btn controller-status`, never `btn-primary`, in one of these forms:
  - **Connect controller button** — label `Connect controller`, no dot. Shown until a controller has connected in this page session or the browser has refused MIDI permission, so also after an unsupported browser, no device found, or a dismissed sheet. Once a controller has connected in the page session, this form never returns. This click is also the page's audio-unlock click, and it requests MIDI permission; it opens the sheet at `Requesting access`.
  - **Connected badge** — `btn controller-status is-badge`: `status-dot is-success`, then `controller-status-label` with the device's name (cut with an ellipsis when longer than the label area; the full name in the `title` attribute, shown on hover, and in the sheet). Also shown when the same device reattaches by itself between sessions (see the no-controller badge). Opens the sheet at `Connected`.
  - **No-controller badge** — `btn controller-status is-badge`: `status-dot is-neutral`, then `controller-status-label` "No controller". Shown once a controller that had connected in this page session is no longer attached: disconnected by the player, lost in a session that has since ended, or unplugged between sessions. Between sessions (Idle or Review) an unplugged controller keeps its selection: this badge shows while it is away, never error-toned and with no countdown; the same device plugged back in reattaches by itself, with no click, no sheet and no transposition check, and the badge returns to the connected badge; a different device plugged in is not picked up and connects only through the sheet. A controller still away when a session ends keeps its selection into the Review the same way. A Start click while the selected controller is away starts a no-controller session: this badge stays, disabled, and the same device plugged back in during that session is not reattached until the session ends. It never reverts to the `Connect controller` form. Opens the sheet at `Requesting access`.
  - **MIDI-blocked badge** — `btn controller-status is-badge is-error`: `status-dot is-error`, then `controller-status-label` "MIDI access blocked". Shown once the browser has refused MIDI permission, until a later request succeeds. That request then decides the form: the connected badge if it connects a device; otherwise the no-controller badge if a controller had connected earlier in this page session, or the `Connect controller` button only if none ever had. Opens the sheet at `Requesting access`, which lands on `Permission denied` again while the browser still blocks it.
  - **Disconnected badge** (session only) — `btn controller-status is-badge is-error`: `status-dot is-error`, then `controller-status-label` "Controller disconnected". Shown only while a lost controller's countdown runs (see States, "Controller lost mid-session").
- **[v2 new]** During a session, `controller-status` is a status display only: its `button` carries `disabled`. The badge forms keep full strength while disabled (`controller-status is-badge` in its disabled state is not dimmed and shows no hover); the `Connect controller` form takes the ordinary `btn` disabled look. It is never removed, replaced, or resized because a session starts, so the header does not shift. It becomes interactive again at Idle and in the Review. When the connection sheet closes, focus goes to the session action if it is enabled, else to the phrase action if it is enabled, else back to `controller-status`, the element that opened the sheet, which is always interactive outside a session (both header actions are disabled in **Loading** and under an unsupported rhythm combination).
- **[v2 new]** Only the MIDI-blocked and disconnected badges use the error tone; every other form is neutral. Every form carries words, so colour is never the only signal.
- **[v2 new]** Every form of `controller-status` has one width, the `Connect controller` button included. `controller-status-label` has the fixed inline size `--controller-status-label-inline-size`, sized for the longest fixed label, "Controller disconnected"; a shorter label leaves the rest of the label area empty, and a longer device name is cut with an ellipsis. The button itself has the fixed content inline size `--controller-status-inline-size` (a badge's dot, gap and label area) and `--text-sm` text in every form, so the `Connect controller` words sit centred in the same box a badge fills. Changing between `Connect controller`, a device name, "No controller", "MIDI access blocked" and "Controller disconnected" never moves `score-context`, `theme-control`, the phrase action, or anything else in the header, at any named breakpoint.
- `theme-control segmented-control` uses `System`, `Light`, and `Dark`. `System` follows the operating-system preference; `Light` and `Dark` set a manual presentation override. This selection changes presentation only: it cannot change a phrase, any control value, generation request, seed, selected profile, or result.
- **[v2 changed]** The header ends with two action slots, in this order: the **phrase action** (`btn btn-lg`, the one whole-phrase action: `Generate phrase` before a result, otherwise `Regenerate phrase`, or `Retry generation` / `Retry notation` in the error states below) and the **session action** (`btn btn-lg session-action`, reading `Start session` or `Stop`). Each slot has one position; neither is ever removed. Primary emphasis (`btn-primary` added) sits on the next useful step, and exactly one of the two carries it:

  | Workspace state                                                                 | Phrase action                                    | Session action                                                |
  | ------------------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------- |
  | **Empty**, **Initial generation error**, **Generation error** (phrase retained) | `Generate phrase` / `Retry generation`, primary  | `Start session`, secondary, disabled                          |
  | **Ready**                                                                       | `Regenerate phrase`, secondary                   | `Start session`, primary                                      |
  | **Loading**                                                                     | disabled, `is-loading`, secondary                | `Start session`, primary, disabled until the new phrase lands |
  | **Notation error**, **Notation error over a retained generation failure**       | `Retry notation`, primary                        | `Start session`, secondary, disabled                          |
  | **Needs more room**                                                             | `Regenerate phrase`, secondary                   | `Start session`, primary, disabled until the notice clears    |
  | **Needs more room** under a generation-failure banner                           | `Retry generation`, primary                      | `Start session`, secondary, disabled                          |
  | **Unsupported rhythm combination**                                              | disabled (`Retry notation` excepted, see States) | `Start session`, disabled                                     |
  | **Session count-in**, **Session running**, and every other session state        | disabled, in place, secondary                    | `Stop`, primary                                               |
  | **Review showing** (any idle state underneath)                                  | disabled, in place, secondary                    | `Close review`, primary                                       |

  A disabled action keeps its emphasis and takes `.btn`'s disabled look. The loading label of a clicked `Retry notation` follows the Loading row.

- **[v2 new]** `session-action` has the fixed inline size `--session-action-inline-size`, shared by `Start session` and `Stop` in both emphases, so a label or emphasis change never moves the header. A Start click leaves focus on the button, which now reads `Stop`; Space or Enter then stops. There is no global keyboard shortcut for either. When a session ends, however it ends, focus moves to the session action, which reads `Start session` again after a session ended during its count-in, and `Close review` after a session end that opens the Review (see States, **Review showing**). `Close review` shares the fixed inline size; it is primary and always enabled while the Review shows.
- **[v2 new]** `session-cue-row` sits between the generation-failure banner's position and `staff-viewport`, always present at the fixed block size `--session-cue-row-block-size`, and holds at most one child at a time, by priority: the disconnect banner, then the count-in (the banner takes the row from a running count-in, which keeps clicking; if the same device reattaches before beat 4, the row shows the count-in again), then the struggling notice, then the starting-note line; with none of them it is an empty row. On the phone during a session, `session-cue-actions` sits at the row's trailing end beside whichever of these it holds (see below). It is not a live region, and its children are static text; nothing in it is announced. Its content changes with no animation.
  - `start-note-line` reads "Play this note to start: {note}". `{note}` is phrase 1's first attacked note in the instrument profile's written pitch, spelled as on the staff, with its octave number, in a `strong` (for example `B♭4`, octave 4 being the one starting on middle C). Neutral text colour, `--text-md`. Shown only when a starting note could start a session: at **Ready** with a controller attached. Hidden when no controller is attached, including while the selected controller is away; while the generation-failure banner shows, even over a retained phrase; and while the connection sheet is open. More generally, hidden whenever `Start session` is disabled.
  - `count-in` is an `ol` of four `count-in-beat` items reading `1`, `2`, `3`, `4`. At the start of the count-in all four show, muted; on each click, on the audio clock, the beat that sounds takes `is-current` and the one before it moves to `is-past`. After beat 4 the row empties.
  - The disconnect banner: `inline-alert alert-error session-alert`, as specified under States, **Controller lost mid-session**. Its sentence is at `--text-lg` and its countdown at `--text-2xl`, bold, inline in the sentence. Below `bp-tablet-landscape` it takes a shorter wording, without its `session-alert-clause`, so it fits the row beside `session-cue-actions`.
  - The struggling notice: `inline-alert alert-notice session-alert` with one `session-alert-text` reading "The generator is struggling with these settings." Neutral tone, body size, never error-toned.
  - `session-cue-actions`, below `bp-tablet-landscape` only, rendered from the session's start (count-in included) until it ends and absent at idle and in the Review: a compact `Stop` (`btn btn-primary`, not `btn-lg`, no fixed inline size), then the `Volume` button (`btn` in its own `mix-volume`, `aria-expanded`, `aria-controls` naming the same volume `popover` as the toolbar's `Volume`). The compact `Stop` does exactly what the header's `Stop` does. The compact `Volume` opens that one popover anchored under itself, with the same two sliders and levels; the popover follows the rules of the toolbar's `Volume` below. The session start has already closed a popover opened before it (see `mix-controls`), so the compact `Volume` always appears with it closed. If the popover is open from the compact `Volume` when the session ends, it closes with it. The header's `Stop` and the toolbar's `Backing`, `Click` and `Volume` stay where they are, unchanged, even when scrolled out of view.
  - `review-link` (`btn review-link`, "Review last session"), at the row's trailing end at idle while a Review exists and is not showing (after `Close review`), in every idle state, beside `start-note-line` or alone. It is removed when a session starts; if it had focus when the starting note started the session, focus moves to the session action (now `Stop`); focus anywhere else is left where it is. Activation shows the Review again (see States, **Review showing**) and moves focus to its title; see `screens/last-session-review/handoff.md`.
- **[v2 new]** `mix-controls` sits in `score-toolbar` after `generation-status`. It is never locked: fully interactive at idle and during a session, in every workspace state. While the Review shows it stays in view and usable, `score-toolbar` staying above `review-panel`.
  - Two toggle buttons, `btn toggle-button` with `aria-pressed`, in this order: `Backing` then `Click`. The visible label is the name followed by `toggle-button-state` reading `on` or `off`; the accessible name is the name alone, and `toggle-button-state` is `aria-hidden`, since `aria-pressed` carries the state. Both default to on. Turning `Click` off never silences the count-in.
  - The `Volume` button (`btn`, `aria-expanded`, `aria-controls` naming the popover) toggles a `popover` holding two `field-group`s, `Backing volume` and `Click volume`, each a `field-label` and a `range-input`. Each slider's minimum, maximum, step and initial value come from `--mix-backing-volume-min` or `--mix-click-volume-min`, then `--mix-volume-max`, `--mix-volume-step`, and `--mix-backing-volume-default` or `--mix-click-volume-default` (proposed placeholders, pending listening tests). The click slider's minimum is never silent; the backing slider's minimum is silence. A slider stays live while its channel is toggled off, and its level applies when the channel is turned back on. Levels, like the toggles, hold for the page session and reset on reload.
  - Opening the popover moves focus to its first slider. Escape closes it and returns focus to `Volume`; a pointer press outside it closes it without moving focus; Tab moving focus out of it closes it. It is the one element allowed to cover part of the staff; nothing else in the workspace opens over it.

## Notation Contract

- `staff-content` renders in the currently selected instrument profile's own written pitch, transposed from concert-pitch events by that profile's own fixed chromatic and diatonic transposition, always in treble G2 clef. There is no separate notation-display selector and no Concert override: C MIDI keyboard is a unison transposition, B-flat tenor saxophone a major ninth, E-flat alto saxophone a major sixth. The transposition transforms written notes, key, written-key label, chord roots, and the slash bass, if a chord symbol ever carries one (current harmony produces none), while preserving chord quality, alterations, extensions, additions, and omissions, and never alters the concert-pitch events themselves.
- The key signature is spelled from the player's written-key selection directly, not re-derived from the concert tonal center.
- The score includes the applicable clef, key signature, 4/4 signature, rhythmic glyphs, rests, beams, ties, accidentals, barlines, and chord symbols. Chord symbols — root and, if a chord symbol ever carries one (current harmony produces none), slash bass — follow the same written-pitch transposition as every other written element above.
- `measure-slot` boundaries represent real measure extents from engraving layout. They do not invent beat positions or vertically place pitch glyphs in CSS.
- **[v2 changed]** The layout refuses to show a phrase until all four measure durations validate. A phrase must not be cut off, horizontally scrolled, shrunk below its legibility floor (the minimum engraving scale at which the score stays readable), or split into more than two staff systems at supported breakpoints. The staff area's height is the two reserved system positions below, not the phrase's content.
- **[v2 changed]** At `bp-tablet-landscape` and above, the score always engraves as exactly one staff system holding all four measures; if it cannot fit at the legibility floor, **Room for the staff** below applies, never the notation-error state.
- **[v2 changed]** Below `bp-tablet-landscape`, the score always engraves in the split layout, at idle as during a session: two staff systems of two measures each within the same staff area — bars 1-2 on the top system, bars 3-4 on the bottom — with clef and key signature repeated on the second system and the 4/4 time signature shown only on the first system. It never first attempts one system, however short the phrase. All four `measure-slot` regions stay visibly equal in width in both the one-system and split layouts, and in the split layout the two systems' measure columns stay aligned with each other. If the split layout cannot fit at the legibility floor, **Room for the staff** below applies, never the notation-error state.
- **[v2 changed]** The staff area always reserves two staff systems, one above the other, in every state (**Empty**, **Loading**, **Ready**, the error states, and every session state), so a session start never changes its size. Each system position has one block size for the current viewport, set by the notation layout and the same for both positions, never by a phrase's content (below `bp-tablet-landscape` it follows the height-fit scale in the next item); at idle, a phrase whose content does not fit its system position at the legibility floor is regenerated (see **Room for the staff** below). At `bp-tablet-landscape` and above, where one system holds all four measures, the idle phrase sits on the top system and the bottom system position is blank: no staff lines, no placeholder. Below `bp-tablet-landscape`, in the split layout, the idle phrase already fills both. During a session the systems refill as defined in `flows/play-session/`; a cleared system is blank until its refill enters.
- **[v2 changed]** **Scale below `bp-tablet-landscape`.** The engraving scale is the largest that fits both the width and the height, capped at the notation maximum and never below the legibility floor. Height: `session-cue-row` and both system positions, with `staff-frame`'s block padding and border, fit together inside the small viewport height (browser toolbars showing); the two positions' share of it is `--staff-systems-phone-block-budget`. Below `bp-tablet-landscape`, `staff-frame`'s block padding is `--staff-frame-padding-block-phone`, smaller than its usual `--staff-frame-padding`, which it keeps on the inline sides (see Responsive Behavior). `staff-frame` has no fixed minimum block size there: its block size is the two system positions at the height-fit scale, which depends on the viewport and never on a phrase, so it is the same in every state, at idle and in a session, and a refill never changes it; a phrase whose width needs a smaller scale draws smaller within its positions. Because the budget uses the small viewport height, a browser toolbar hiding or reappearing never changes the scale and never redraws the staff. If even the legibility floor cannot fit the height, the staff has no room: at idle the workspace shows **Needs more room** (see **Room for the staff** below and States), no session can start, and a running session ends (see Responsive Behavior). At `bp-tablet-landscape` and up nothing changes: `staff-frame` keeps its fixed minimum block size and the scale fits the width only.
- **[v2 new]** **System position size and staff placement.** The two system positions share one block size in staff spaces, the same for every instrument profile and at every breakpoint, so neither a phrase nor a profile switch ever changes the staff area's size; only the scale turns it into a block size on screen.
  - **Size.** A position holds the tallest ink any one profile's written range can produce, with about one staff space clear at each end: chord symbols over the profile's highest written notes, the ledger lines under its lowest, stems, beams, ties, and `start-note-marker` (see **Start marker**). It is not sized for the highest ink of one profile stacked over the lowest ink of another, which no phrase can reach: the saxophones reach high (written up to C6, with chord symbols above) and never below written C4; the C MIDI keyboard reaches low (written down to C3, with its ledger lines) and never above written C5.
  - **Placement.** Within the position, the staff is placed for the selected profile's written range: a range that reaches high gets more room above the staff, one that reaches low more room below. The placement is derived from the profile's written range, never from a table of profiles, so a future profile needs no new rule; a profile whose range would need a taller position makes the one shared size taller for every profile.
  - The placement changes only with the profile, never with a phrase, so a refill, a repeat or a session start never moves a staff line. A profile switch, which always replaces the phrase, may move the staff within its positions; the new phrase enters with the usual `staff-content` fade and the staff area keeps its size.
  - Whether every profile's ink stays inside the position is checked by the engraving calibration, which measures real engraved phrases for every profile, start marker included.
- **[v2 changed]** **Room for the staff.** At idle, a phrase that cannot be drawn at the legibility floor fails for one of two reasons, handled apart; neither ever takes the notation-error state, which is kept for failures a retry can cure.
  - **No room.** The viewport cannot hold the staff layout for its breakpoint at the legibility floor, whatever phrase it holds: it is too narrow for the layout's fixed parts (clef, key signature for the current written key, time signature) with four measures at the engraver's minimum measure width, or, below `bp-tablet-landscape`, too short for the floor (see **Scale below `bp-tablet-landscape`**). The workspace shows **Needs more room** with its no-room sentence (see States) and runs no fresh-seed retries, since no phrase could fit.
  - **Too many notes.** The viewport has room, but this phrase's notes need more width than the legibility floor allows. The phrase is never shown: the app quietly generates a replacement with a fresh seed, up to three times, the retries a session's look-ahead takes (at idle there is no carry-in and no deadline; see `flows/play-session/handoff.md`, Look-ahead), all inside one **Loading**, which simply lasts longer. Each attempt takes the note density the viewport gives when it is generated (see Components and Content, Note density), as every generation does. If a crossing of `bp-tablet-landscape` during these retries makes the rhythm combination unsupported (a widening, with a stored `Sixteenth`), the retries stop, no attempt is drawn, and the workspace shows **Empty** with the unsupported-rhythm alert, as a round under the notice does (see States, **Needs more room**, **Under an unsupported rhythm combination**). The first phrase that fits lands in **Ready**; the retries show nothing and announce nothing beyond the Loading's own `Generating phrase` and `Phrase ready`. If every attempt produced a phrase too wide to fit, the workspace shows **Needs more room** with its too-many-notes sentence, and no attempt is drawn. An attempt that finds no phrase at all ends the run with the ordinary generation-failure banner and its failure string, as any idle generation failure does: **Generation error** when a phrase stayed on screen through the Loading, **Initial generation error** when the Loading showed no score (see States).
  - This applies to every idle engraving: a generation, a regeneration, a `Retry generation`, a profile-switch regeneration, the new phrase generated when **Needs more room** clears, a round of retries started under its too-many-notes sentence, a session ended during the count-in (see States), and a viewport change at idle that leaves the phrase on screen too wide. While the rhythm combination is unsupported no generation can run, so a phrase on screen that stops fitting is not drawn, and the workspace shows **Empty** with the unsupported-rhythm alert (see States, **Needs more room**, **Under an unsupported rhythm combination**); one widening past `bp-tablet-landscape` can do both at once, switching to one system per phrase and making a stored `Sixteenth` combination unsupported. A window with no room at all still shows **Needs more room** with its no-room sentence.
- **[v2 new]** **Session staff layout.** A session keeps the layout the rules above give at the breakpoint where it starts, and holds it until it ends, even across `bp-tablet-landscape` (see Responsive Behavior): below `bp-tablet-landscape`, the split layout (bars 1–2 on the top system, bars 3–4 on the bottom); at `bp-tablet-landscape` and up, one system per phrase. Phrase 1 is already shown in that layout at idle, so a session start re-engraves nothing and moves no note. During a session, engraving in the held layout at the legibility floor at the current viewport size is part of what makes a look-ahead phrase valid: a phrase that does not fit is a failed generation attempt and takes the normal fresh-seed retries (see States, **Session running**), invisibly. The notation-error state is never shown during a session: a look-ahead phrase that does not fit is retried; a repeat is the phrase just shown, already in the held layout; and on a viewport change, if the systems on screen or any material already checked and waiting to be drawn no longer fit, the session ends rather than showing it (see Responsive Behavior).
- **[v2 new]** **Start marker.** At idle, whenever `start-note-line` is shown, the notation pipeline draws `start-note-marker` above phrase 1's first attacked note: a filled isosceles triangle, apex down, 1.2 staff spaces wide and 1 space tall, centred horizontally on the notehead. It is sized in staff spaces by the engraver, coloured by the class, and removed when `start-note-line` goes, including at the count-in's first click. Its base sits half a space above the higher of two edges: the top of the note's own ink (notehead, stem, flag, accidental, ledger lines, and a beam over its stem) and the staff's top line, so it never sits inside the staff, even over a low note whose stem ends within it. Over a note that carries a chord symbol, it sits there only where the gap from that edge up to the chord symbol's bottom is at least 2 spaces (half a space clear above and below it); otherwise its base sits half a space above the chord symbol's top. The chord symbol is never moved for it. It stays inside the top system position; the shared position size allows for it (see **System position size and staff placement**).
- **[v2 new]** **Playhead band.** During **Session running** the notation pipeline draws one `playhead-band` rectangle for the measure being played: an opaque `--color-playhead-band` fill, never an opacity, drawn behind every glyph of its system, staff lines and barlines included. Horizontally it runs from the measure's opening barline to its closing barline; on a system's first measure it starts where the measure's notes start, after the clef, key signature and time signature, so it never tints them. Vertically it runs from one staff space above the top line to one space below the bottom line, and, where a notehead on that system lies further out, to half a space past that notehead's outer edge, never beyond the system position. The vertical extent is taken over the whole system, not measure by measure, so the band keeps one height while it steps along a system and only its horizontal position moves with the music. Stems, beams, ties and chord symbols that reach beyond it are not covered. On each barline, on the audio clock, it is moved to the next measure, on whichever system that measure sits; it never glides and has no transition. It is absent at idle, during the count-in, and once the session ends.
- **[v2 new]** **Acknowledgement.** When an expected note is matched, the notation pipeline adds `note-ack` to that note's own notehead, stem, flag, accidental and augmentation dot, and nothing else: a beam shared with other notes, its ledger lines, a tie arc and the chord symbol attached to the note stay in the staff ink, including where the engraver draws the chord symbol inside the note's own group. A tied continuation's notehead, stem, flag, accidental and augmentation dot take `note-ack` together with the note's attack; the tie arc joining them stays in the staff ink, as a beam does. The change is instant, with no animation, and holds until the note's system is cleared for refill. A missed or wrong note changes nothing, and the played note is never drawn.
- On profile selection while a phrase exists, never validate the old phrase against the new active range and never retain or redraw it: keep the written key, collection, and every other control, take a fresh seed, and regenerate the complete phrase as a replacement under the new profile. The one exception is a rhythm-control combination (rhythmic variety, note density, syncopation, silence density) that is already unsupported at the moment of the switch: the switch still applies, but the phrase clears and the workspace returns to the empty state instead of regenerating — see States, "Unsupported rhythm combination." With no phrase shown yet, a profile switch only changes the selected profile; nothing generates.
