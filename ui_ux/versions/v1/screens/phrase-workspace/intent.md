# Phrase Workspace Intent

The score is deliberately the focal point. A player should be able to sight-read the phrase without searching for where bar three begins or which chord governs a note. Four visibly equal measure regions, strong barlines, and chord symbols placed above their harmonic entry give the phrase its form at a glance. At `bp-tablet-landscape` and above, that takes the form of one unbroken staff system holding all four measures. On phone landscape, below `bp-tablet-landscape`, the same legibility floor that keeps the score readable at a distance can make one system too small to hold all four bars; rather than shrink the score past that floor, the workspace falls back to two aligned staff systems of two measures each, so the phrase still reads as one four-bar form split at a natural halfway point rather than as compressed or illegible notation.

The header gives only essential reading context: meter, tempo, and the whole-phrase action. There is no separate notation-display control to place there — the score always renders in the currently selected instrument profile's own written pitch. It omits generator internals, seed data, and a performance interpretation because these do not help a player read the proposal. `control-summary`, a single muted line after the control section's title and intro copy but before its control groups, restates written key, collection, musical profile (or the custom state), tension, and leapiness as one compact settings line so a player scrolling into controls does not have to re-scan every field-group to know what they are about to change; it is static text, not a live region, since it only mirrors state the controls already show. Instrument profile and its active range stay with the instrument-profile control itself, in `profile-range-summary`, because that information is explanatory metadata for one specific choice rather than a top-level setting a player needs restated at a glance.

The score fills the first content row on every landscape target. Controls follow it in the vertical reading order, so a player can read the staff from a distance before scrolling to shape a replacement. Wide displays orient control groups horizontally across the page; landscape phones stack them into a compact scrollable section. The character group is static rather than disclosed: it holds only Arpeggio chaos, first release has no second character-level control, and hiding a group's only control behind a toggle would add friction without protecting the player from anything.

The header takes only the space necessary for brand, meter and tempo, theme override, and the whole-phrase action. The screen must not shrink notation to accommodate UI chrome. When available space is constrained, control content moves below the score before the score uses a smaller engraving scale. The defined landscape targets are a product constraint; portrait mobile and tablet views receive a rotate-device message instead of an illegible rearrangement, while desktop remains usable when it has sufficient width. A profile switch never carries a phrase forward: with a phrase shown, it always regenerates a complete replacement in the new profile's written pitch, with a fresh seed, rather than testing whether the old phrase would still fit. The UI makes that regenerated replacement clear through the normal stable-frame loading and fade sequence rather than presenting a silent pitch transposition.
