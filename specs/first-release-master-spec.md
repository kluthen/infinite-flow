# Infinite Flow: First-Release Master Specification

Status: draft v2.0 - ready for implementation handoff

Amended for the v1.0 gate (2026-09-26): D56–D60, D73. The instrument profile now carries its transposition and the key is chosen in written pitch; rhythmic variety is added and the mixed note density is retired; musical-profile behavior is gated by named capabilities. The rhythmic-variety value sets are fixed by a feasibility review before implementation (see Rhythmic variety below).

## Objective

Build a client-side web application that generates one coherent, staff-notated four-measure musical proposal for a selected first-release instrument profile. The player selects musical controls and explicitly regenerates the entire phrase to hear and see a different variation. The product's immediate value is a musically legible proposal, not playback, accompaniment, scoring, or an endless autonomous session.

## Scope

### Included

- Generate exactly four measures in 4/4 at a user-selected stable BPM.
- Render the complete proposal in conventional staff notation with chord labels or harmonic context.
- Support the phrase workspace on mobile and tablet devices in landscape orientation and on desktop when sufficient width is available. Portrait mobile and tablet views show a rotate-device notice instead of an interactive score.
- Generate and retain one concert-pitch event timeline for every phrase.
- Support declarative C MIDI keyboard, B-flat tenor saxophone, and E-flat alto saxophone instrument profiles. Each supplies an explicit inclusive active concert range and register-window policy to generation, and a concert-to-written transposition to request construction and notation.
- Show the phrase in the selected instrument profile's written pitch: concert pitch for the C MIDI keyboard, a major ninth above concert for the B-flat tenor saxophone, and a major sixth above concert for the E-flat alto saxophone. There is no separate notation-display selection and no Concert-display override. Transposition never changes generated pitches, harmony, the seed, or the active range policy.
- Follow the operating-system light/dark preference on first load, with a manual light or dark override available to the player.
- Offer a style-neutral default musical profile and an optional jazz musical profile, each with the defined first-release preset values.
- Offer controls for tonal center, scale or mode, harmonic motion, tension, note density, rhythmic variety, syncopation, silence density, contour, register, leapiness, and arpeggio chaos.
- Regenerate all four measures from the same controls with a new random seed. Retain the seed so a result can be exactly reproduced internally.

### Explicitly Excluded

- Generated lead-line playback.
- Required backing or accompaniment. BPM-aligned backing may be added only as a non-blocking enhancement.
- MIDI controller connection, input, match or mismatch feedback, timing evaluation, and MIDI-seeded continuation.
- Microphone capture, audio-to-note transcription, and acoustic pitch detection.
- Continuous generation, a rolling staff, seed-phrase capture, automatic key detection, phrase adaptation, or long-term personalization.
- Tempo variation, meters other than 4/4, pulse-feel controls, direct chord-progression authoring, altered dominants, substitutions, modulation, and altissimo.
- Performance scores, grades, rankings, or a pass/fail interpretation of player input.
- Persistence. Sessions are ephemeral; later work may capture and export them.

## Player Controls

- **Tempo:** one stable BPM for the entire phrase, selectable from 60 through 240 BPM in 10 BPM increments. The default is 90 BPM.
- **Tonal context:** one of all twelve pitch classes plus a collection, read in the selected instrument profile's **written** pitch: the player picks the key as it is written for their instrument. C Ionian on the B-flat tenor saxophone is written C major with an empty key signature and sounds as concert B-flat Ionian; on the C MIDI keyboard, written and concert pitch are the same. Request construction converts the written tonal center to the concert tonal center by removing the instrument profile's chromatic transposition (modulo 12); every planner receives only the concert tonal context. The display label follows the first-release enharmonic-spelling rule. The default is C Ionian.
- **Collection:** major, minor, Ionian, Dorian, Phrygian, Lydian, Mixolydian, Aeolian, or Locrian. The seven named church modes are all available; major and Ionian, and minor and Aeolian, remain separately selectable labels.
- **Harmonic motion:** static, gentle diatonic motion, or active diatonic motion. The player does not enter chord progressions.
- **Tension arc:** `Settled`, `Lift`, `Build`, or `Edge`, defaulting to `Lift`. It schedules permitted diatonic instability and local resolution across the phrase; it is not an objective tension score and cannot relax another selected control's limits.
- **Note density:** quarter notes, eighth notes, or sixteenth notes. The selected density is the phrase's dominant note value. There is no mixed-subdivision density; `Heavily varied` rhythmic variety covers that need.
- **Rhythmic variety:** `Strict`, `Slightly varied`, or `Heavily varied`, defaulting to `Slightly varied`. It sets how likely note values other than the selected note density are to appear, both shorter and longer. `Strict` allows only the selected value, plus the rests and ties that silence density and syncopation produce. `Slightly varied` matches the variety the quarter-note density produced before this amendment (occasional dotted values, half notes, and eighths). `Heavily varied` makes other values common while the selected value stays dominant. At sixteenth-note density only longer values can appear, because the grammar has nothing shorter. A rhythm-grammar feasibility review, completed and confirmed by the user before implementation, fixes the exact value set and weighting per level and density, how dominance is measured, variety's place in the tie-break order, and any change to the blocked rhythm settings. Its goals are no new blocked rhythm setting, and a `Heavily varied` level that never blocks. "Rhythmic variety" is the canonical term; the player-facing label belongs to the UI documents.
- **Syncopation:** straight, occasional offbeat placement, or active displacement.
- **Silence density:** sparse rests, conversational space, or breath-heavy phrasing.
- **Contour:** rising, falling, arch, or wandering.
- **Register:** `Low`, `Middle`, `High`, or `Varying` within the selected instrument profile's active concert range and register-window policy. `Varying` is a player-selectable value, not a separate range: for each generation request, the seeded planner selects one eligible `Low`, `Middle`, or `High` register policy for the complete phrase. An eligible policy is one that can produce a phrase within the profile-derived active range while satisfying the selected contour, musical profile, leapiness, and recovery rules. If no eligible policy can produce a valid phrase, generation fails explicitly rather than relaxing a hard constraint.
- **Leapiness:** `Smooth`, `Shaped`, `Leaping`, or `Angular`, defaulting to `Shaped`. It sets adjacent-interval caps, a phrase leap budget, and recovery obligations.
- **Arpeggio chaos:** predictable nearby chord-tone order through reordered chord tones and stronger interval contrast. It never allows pitches outside the selected musical profile or ignores contour, range, and resolution constraints.
- **Musical profile preset:** neutral by default or jazz. This is distinct from the selected instrument profile. The neutral preset's complete bundle is static harmonic motion, quarter-note density, `Slightly varied` rhythmic variety, straight syncopation, sparse rests, arch contour, and `Middle` register. The jazz preset's complete bundle is gentle diatonic harmonic motion, eighth-note density, `Slightly varied` rhythmic variety, occasional offbeats, conversational space, wandering contour, and `Varying` register. Selecting either preset replaces all seven preset-controlled controls with that complete bundle, regardless of their current values.
- **Custom configuration after a preset:** A manual change to any preset-controlled control after selecting a preset creates a custom current configuration. It preserves the selected musical profile's grammar while using the manually selected control values; it does not mutate either preset definition. Selecting neutral or jazz again discards the custom values and reapplies that preset's complete bundle.

## Musical Behavior

### Shared Constraints

- The output is one short phrase, not four independently random measures.
- Every measure fills exactly four beats. The selected note density is the dominant note value; rhythmic variety governs how often other values appear.
- All generated source pitches are inside the selected instrument profile's inclusive active concert range. The generation boundary obtains this active range and the selected register-window policy explicitly from the validated instrument profile.
- Phrase regeneration must be deterministic for a given complete request and seed.
- With `Varying` register, the seed deterministically selects one eligible non-varying register policy for the whole phrase. It must not change policies between measures or individual notes, and it must not extend or otherwise relax the profile-derived active range, contour, musical profile, leapiness, or recovery rules.
- The four-bar phrase ends open so the player can continue playing. A closed tonic ending is a later option.
- The request contains the selected values, including musical profile preset, tension arc, leapiness, and rhythmic variety, with the tonal center already converted to concert pitch. Applying a theme is not a generation request and cannot alter the phrase.

### Tension Arc

- `Settled` prioritizes chord tones on metrically strong locations and resolves an active scale degree by the next strong onset.
- `Lift` permits a small amount of active diatonic motion in measures 2-3 and one resolution deferred to the following beat or bar.
- `Build` concentrates active notes and permits one limited two-note diatonic approach in the middle of the phrase.
- `Edge` places the greatest permitted instability in measure 3 and uses the latest valid local resolution.
- At every level, local dissonances, appoggiaturas, jazz approaches, and jazz enclosures resolve before the final sounding event. The endpoint remains open: use a final dominant chord tone when generated tonal motion ends on dominant; with static tonic prolongation or modal material, use a profile-approved non-final tonic-area continuation such as scale degree 5, never an asserted tonic closure.
- Tension ranks only legal candidates. In priority order, hard feasibility and cadence policy; musical profile, tonal collection, range, and contour; density and silence budgets; syncopation onset plan; leapiness and arpeggio-chaos candidates; tension ranking; then the seeded deterministic tie-break decide the phrase. Tension cannot add onsets, remove rests, change register, exceed leap limits, or turn syncopation into a monotonic tension control. Where rhythmic variety enters this order is fixed by the rhythm-grammar feasibility review.

### Leapiness

- Measure intervals between adjacent sounding notes only; intervening rests do not count. A step is 1-2 semitones, a skip 3-4, a leap 5-6, and a large leap 7-12. No adjacent interval may exceed an octave.
- `Smooth` permits intervals up to 4 semitones and no leaps; arpeggio chaos cannot create one.
- `Shaped` permits intervals up to 7 semitones, at most 2 leaps, and at most 1 large leap. A large leap recovers immediately; one recognized two-note chord-tone skip pair is permitted.
- `Leaping` permits intervals up to 10 semitones, at most 4 leaps, and at most 2 large leaps. Each large leap recovers immediately or after one recognized same-direction chord-tone run of no more than 3 notes.
- `Angular` permits intervals up to 12 semitones, at most 6 leaps, and at most 3 large leaps, with the same recovery rule. It permits no more than one 3-note arpeggio run per measure or two per phrase.
- These are ceilings, not quotas. After a large leap or recognized run, recovery is an opposite-direction step of 1-2 semitones or short contrary motion of 3-4 semitones. A recognized arpeggio is a coherent 2-3-note same-direction chord-tone run under one harmony; an unrecognized chain of two same-direction leaps is invalid. The planner reserves enough range to satisfy selected contour and recovery before accepting an outward leap.

### Neutral Profile

- Stay entirely inside the selected major, minor, or modal collection.
- Use mostly diatonic chord movement. Static motion sustains tonic or tonic prolongation; gentle and active motion introduce diatonic departure and return. In tonal material, active motion may use tonic, predominant, dominant, then an open dominant arrival. Modal material must not invent a raised leading tone merely to force a dominant cadence.
- Prefer chord tones on beat 1 and at chord changes.
- Use diatonic passing and neighbor tones as controlled movement. At increased tension, allow an accented diatonic appoggiatura that resolves by step; keep it limited and resolution-directed.
- Build bars 1-2 as a rhythmic gesture and bars 3-4 as a related answer that varies an ending, onset, or contour.
- Preserve at least one metrical anchor per bar. Syncopation moves selected events to offbeats or sustains across stronger beats; it does not erase the pulse.
- Use actual rests as phrase boundaries and breath opportunities, not merely lower event count.
- Prefer steps and diatonic thirds. Larger leaps must satisfy the selected leapiness policy, register, contour, range reservation, and recovery rule. Consecutive leaps must form a recognized arpeggio rather than arbitrary zig-zags.

### Jazz Profile

- Reuse the neutral profile's diatonic harmonic plan and phrase construction.
- Permit a one-note chromatic approach from one semitone above or below a target chord tone, immediately resolving to that target.
- Permit a two-note chromatic enclosure around a target chord tone only when the subdivision gives the resolution enough room to be heard.
- Keep approaches and enclosures brief, resolution-directed, and limited. They must not form a new chord, target a non-chord tone, remain unresolved at phrase end, or imply altered harmony.
- These chromatic figures are enabled by the capability _chromatic approach and enclosure figures allowed_, which the jazz musical profile declares and the neutral musical profile does not. Generation checks the capability, never the profile's name.

## Architecture and Boundaries

Generation uses a stable, serializable request/result boundary. The request contains the measure count, meter, BPM, concert tonal context, normalized controls, musical profile preset, selected instrument-profile identity, its explicit active concert range and register-window policy, optional future phrase context, and deterministic seed. The generation boundary consumes the profile-derived range/register policy rather than branching on an instrument identity. The instrument profile's transposition is used only by request construction (to convert the written tonal center to concert pitch) and by notation; no planner reads it. The request does not contain theme preference, browser state, audio state, or mutable session data.

The result is an immutable concert-pitch timeline of measures, chord events, note events, rests, and optional musical annotations. It contains no staff-rendering symbols, written pitches, audio scheduling timestamps, MIDI device messages, or scoring state. A result either satisfies the requested meter and selected-profile hard range constraints or fails explicitly; it must not return an invalid phrase.

Separate components own control mapping, harmony planning, rhythm planning, pitch planning, notation rendering, optional backing arrangement, MIDI input, and later evaluation. A component consumes explicit data from another component rather than internal state. Instrument profiles are validated declarative data: adding a valid profile supplies its identity, concert-pitch range, register-window policy, concert-to-written transposition, and metadata without conditional changes to melodic, harmonic, rhythm, or notation-rendering logic, and without new types, enumeration members, or user-interface branches. Transposition is open data: an integer chromatic semitone count and an integer diatonic letter-step count, validated as a consistent pair, never a closed list of display conventions or a literal-valued type. The first-release values are C MIDI keyboard `+0/+0`, B-flat tenor saxophone `+14/+8` (major ninth), and E-flat alto saxophone `+9/+5` (major sixth). The first-release profiles and inclusive windows are C MIDI keyboard `48-72` with Low `48-60`, Middle `54-66`, and High `60-72`; B-flat tenor saxophone `46-70` with Low `46-58`, Middle `52-64`, and High `58-70`; and E-flat alto saxophone `51-75` with Low `51-63`, Middle `57-69`, and High `63-75`. `Varying` deterministically selects one feasible complete-phrase window from Low, Middle, and High; it never changes window mid-phrase. Musical profiles supply musical policy as data, including named capabilities. Planner and validator behavior is gated on a declared capability, never on a musical-profile name; the first-release capability is _chromatic approach and enclosure figures allowed_ (jazz declares it, neutral does not), and moving to it must leave every generated result unchanged. Neither profile type owns user-interface widgets, browser APIs, scheduling, or persistence.

## Application State, Accessibility, and Layout

The workspace has one active generation or notation operation at a time. While phrase generation is active, the phrase action is disabled and every configuration control is read-only but remains focusable. Controls retain their values and must suppress pointer and keyboard changes; the prior valid score remains visible during regeneration. A generation request is created only by the explicit Generate, Regenerate, or Retry generation action, except when the player switches instrument profile while a phrase is shown. That switch keeps the written tonal center and collection and automatically regenerates the complete phrase with retained controls and a fresh seed. The six note-density, silence, and syncopation settings that have no legal rhythm under the v1 rhythm grammar (the list owned by the unsupported-rhythm-settings rule; the rhythmic-variety feasibility review may revise it) block generation with an explanatory status message. If an instrument-profile switch happens while one of them is selected, the switch still applies, the phrase is cleared to the empty workspace, and no generation runs.

An initial generation failure leaves the empty workspace visible and exposes a retry action. A later generation failure retains the prior valid score and exposes a retry action. Retrying a failed generation builds a new request from the current controls and musical-profile selection with a fresh seed, as Regenerate does; it does not replay the failed request. A notation failure retains valid phrase data but replaces the score content with a retryable notation error; retry notation reuses that phrase data rather than generating a new seed. Theme changes apply immediately without a generation or notation operation. Required generation, notation, controls, and the current phrase remain available offline; unavailable optional browser capabilities must not block the phrase loop.

Every discrete control is keyboard-operable as a labeled single-select radiogroup with one checked option. The one exception is the musical-profile preset group in the custom state: after a manual edit to a preset-controlled field, neither Neutral nor Jazz is checked, the first option is the sole tab stop, and a status line names the retained grammar. Otherwise, the checked option is the sole tab stop; arrow-key navigation selects and focuses the adjacent option. A persistent polite live-status region announces generation start, ready, and failure, but not ordinary control or presentation changes. Interactive controls provide a visible focus indicator and a minimum 44 CSS-pixel target. Reduced-motion preference suppresses nonessential transitions and phrase-replacement animation.

The workspace supports landscape mobile and tablet layouts and desktop layouts at or above `90rem` in either orientation. Layout behavior changes at `48rem`, `64rem`, and `90rem`; below `90rem` in portrait, the application shows a rotate-device notice instead of interactive phrase controls. At `64rem` and above, all four measures appear in one staff system. Below `64rem` (the landscape phone layout), the score uses one staff system when it fits at the legibility floor; otherwise it uses two staff systems of two measures each (measures 1-2, then 3-4). The second line repeats the clef and key signature, and the time signature appears only on the first line. Measures are equal in width and aligned between the two lines. No layout uses horizontal score scrolling, clipping, or more than two systems. If valid phrase data cannot be engraved under these constraints, show the retryable notation error rather than a partial, further-split, or substitute score.

## Notation

Notation renders standard staff notation in treble G2 clef, in the selected instrument profile's written pitch, derived from the concert-pitch timeline by that profile's concert-to-written transposition: C MIDI keyboard `+0 chromatic/+0 diatonic`, B-flat tenor saxophone `+14 chromatic/+8 diatonic` (major ninth), and E-flat alto saxophone `+9 chromatic/+5 diatonic` (major sixth). There is no separately selected display convention and no Concert-display override. Notation cannot mutate the concert timeline, the selected instrument profile, its range/register policy, or any generation control. Apply the transposition to note spelling, key, tonal-center label, chord root, and slash bass, but preserve chord quality, alterations, extensions, additions, and omissions.

Switching the selected instrument profile keeps the selected written tonal center and collection. Because the new profile's transposition can differ, request construction derives a new concert tonal center, and the complete phrase regenerates under the new profile with the retained controls and a fresh seed. The previous phrase is never retained or redrawn in the new profile's written pitch, and source events are never transposed to fit a profile. With no phrase shown, the switch only changes the selection. With a blocked rhythm setting selected, the switch applies and the phrase is cleared without generating. Switching is expected to be rare.

### Enharmonic Spelling

- The written tonal center and collection are the player's selection itself; they are not re-derived from concert pitch. Choose the enharmonic representation that requires the fewest accidentals for that written tonal center and collection. If two representations require the same fewest number of accidentals, choose the sharp representation.
- Apply that one representation consistently to the displayed tonal-center label, key signature, written note accidentals, and chord symbols. No displayed item may use a different enharmonic convention solely because another equivalent spelling is possible.
- Written note, chord-root, and slash-bass spellings are the concert values moved by the selected instrument profile's transposition and spelled under this rule. Spelling must not change concert pitches, harmony, seed, active range policy, or any generation control.

## Definition of Done

- A user can select every chromatic tonal center; major, minor, and each church mode; a 60-240 BPM tempo in 10 BPM increments; and all other first-release controls, then generate a complete four-measure 4/4 phrase. First load uses 90 BPM, written C Ionian on the B-flat tenor saxophone (concert B-flat Ionian), the neutral preset, `Slightly varied` rhythmic variety, `Lift` tension, and `Shaped` leapiness.
- Selecting neutral sets harmonic motion, note density, rhythmic variety, syncopation, silence density, contour, and register to neutral's complete bundle; selecting jazz sets each of those seven controls to jazz's complete bundle. The selection replaces every one of the seven values even when one or more values were manually changed beforehand.
- After a preset selection, manually changing one or more of those seven controls produces a custom current configuration without changing either preset's defined bundle or the selected musical profile's grammar. A later selection of neutral or jazz restores every value in the newly selected preset's complete bundle. Jazz applies `Varying`; for a given complete request and seed, it selects exactly one eligible `Low`, `Middle`, or `High` policy for the complete phrase while retaining all hard musical constraints. The workspace supports landscape mobile and tablet views; a portrait mobile or tablet view shows a rotate-device notice instead of interactive phrase controls.
- Every generated measure is complete, and every generated concert pitch falls inside the selected instrument profile's inclusive active range: C MIDI keyboard `48-72`, B-flat tenor saxophone `46-70`, or E-flat alto saxophone `51-75`. The selected whole-phrase register window is respectively one of C Low `48-60`, Middle `54-66`, High `60-72`; B-flat Low `46-58`, Middle `52-64`, High `58-70`; or E-flat Low `51-63`, Middle `57-69`, High `63-75`.
- Every result satisfies the selected tension-arc and leapiness caps, budgets, arpeggio-run rules, recovery rules, local-resolution requirement, and open-ending requirement.
- The neutral profile contains no chromatic pitches outside its selected collection, substitutions, altered dominants, or chromatic enclosures.
- The jazz preset sets gentle diatonic harmonic motion. The jazz profile adds only bounded chromatic approaches and enclosures that immediately resolve to chord-tone targets; its harmony remains diatonic.
- Chromatic approaches and enclosures are gated by the _chromatic approach and enclosure figures allowed_ capability that the jazz musical profile declares; no planner or validator compares a musical-profile name to decide behavior. Introducing the capability leaves every golden fixture byte-identical to its pre-change baseline (this change lands separately from rhythmic variety, which is expected to change fixtures).
- Re-generating changes the seed while preserving controls; supplying the same full request and seed reproduces the same result.
- For every supported written tonal center, collection, and instrument profile, standard staff notation uses treble G2 clef, the instrument profile's written pitch, and the enharmonic spelling of the selected written key requiring the fewest accidentals; equal minima use sharps. The resulting tonal-center label, key signature, note accidentals, chord roots, and slash bass use the same spelling convention; chord quality remains unchanged. Notation cannot change the concert timeline or the profile-derived generator policy.
- Written key: C Ionian on the B-flat tenor saxophone shows the label C, an empty key signature, and written notes a major ninth above the generated concert pitches; its request carries concert tonal center B-flat (pitch class 10) Ionian. C Ionian on the E-flat alto saxophone shows an empty key signature and requests concert E-flat (pitch class 3) Ionian. C Ionian on the C MIDI keyboard requests concert C Ionian and shows an empty key signature, as before this amendment. A mode follows its parent major's signature: written D Dorian on the B-flat tenor saxophone shows an empty signature and requests concert C Dorian.
- Open transposition: adding an instrument profile is one declarative entry plus its validation tests. A test-only profile whose transposition none of the first-release profiles use (for example `+2/+1`, a B-flat soprano instrument, or `+21/+12`, an E-flat baritone saxophone) passes end to end through request construction, spelling, and engraving without any type, enumeration, or user-interface change. No closed display-convention type or literal-valued transposition type remains.
- Switching instrument profile while a phrase is shown keeps the written tonal center and collection, derives the new concert tonal center from the new profile's transposition, retains every other control, and regenerates all four measures with a fresh seed under the new profile; it never retains the previous phrase or transposes source events. Tests cover a switch between each pair of first-release profiles (written key unchanged, concert tonal center recomputed, fresh seed), a switch with no phrase shown (selection only, no generation), and a switch under a blocked rhythm setting (switch applies, phrase cleared, no generation).
- Rhythmic variety offers exactly `Strict`, `Slightly varied`, and `Heavily varied`, defaults to `Slightly varied`, and both presets set `Slightly varied`. Under `Strict`, every attack uses the selected note density's value apart from rests and ties produced by silence density and syncopation. Each level produces exactly the value set the feasibility review fixed, and the selected density stays dominant under the review's measure; tests cover every density and level across the seed matrix. The set of blocked rhythm settings is the one the review fixed.
- Note density offers exactly `Quarter`, `Eighth`, and `Sixteenth`. Control construction and the generation worker's boundary parser reject `Mixed` as an unknown value.
- After these amendments, generation still meets the latency budget: warm p95 at most 250 ms and cold p90 at most 500 ms, measured as in the generation-latency report.
- The initial theme uses the system preference, and a manual light or dark override changes presentation without changing the phrase request or result.
- The application operates entirely in the browser for its required first-release behavior, without server dependency.
- The workspace permits at most one active generation or notation operation. During generation, the action is disabled; configuration controls remain focusable read-only context and cannot change values; a prior valid phrase remains visible. Initial generation failure retains the empty workspace; later failure retains the valid phrase; notation failure retains phrase data but replaces score content with a retryable error. An instrument-profile switch while a phrase is shown is the sole automatic full-phrase regeneration; under a blocked rhythm setting it clears the phrase instead.
- Every control can be operated by keyboard with the defined radiogroup, roving-tab-stop, and arrow-key behavior. A polite live-status region announces generation start, completion, and failure. Controls have visible focus indication and at least 44 CSS-pixel targets; reduced-motion preference disables nonessential animation.
- Required phrase generation and notation function offline without a server or optional browser capability. At `64rem` and `90rem`, layout changes preserve all four measures in a single non-scrolling, unclipped staff system. Below `64rem`, the four measures appear in one such system, or in two aligned two-measure systems when one does not fit at the legibility floor. Below `90rem` in portrait, the application shows a rotate-device notice; desktop at or above `90rem` remains interactive in either orientation. An unrenderable valid phrase shows a retryable notation error rather than partial or substitute notation.

## Deferred Work and Visible Gaps

- Later versions are scoped in [versions/](versions/README.md) and ordered in the [roadmap](roadmap.md); v2 adds the rolling phrase, MIDI acknowledgement, backing playback, and last-session review with export. When MIDI input arrives, incoming note numbers are read as concert pitch and compared with the concert timeline; an input-transposition setting is not planned until a device needs it.
- Optional backing has no decided role yet. If added, it must read the generated harmony and BPM without changing lead generation.
- The exact mechanism by which a later planner may repair a previous planner's voice-leading or playability decision remains open. Any future repair must preserve the component boundaries above.
- Later work may add additional instrument profiles or player-selected range variants through separately validated declarative range/register/transposition definitions, a player-configured instrument, a Concert-display override, rhythmic-variety rates or embellishment settings, and phrase-end controls.
