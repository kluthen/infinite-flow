# Adopted Saxophone Range and Display Profiles

Infinite Flow adopts three declarative, concert-pitch instrument profiles: **C MIDI keyboard `48-72`**, **B-flat tenor saxophone `46-70`**, and **E-flat alto saxophone `51-75`**, with every endpoint inclusive. The saxophone choices deliberately give both instruments the same written working range, C4-C6, while their different transpositions yield distinct sounding MIDI ranges; they are conservative product defaults, not claims about every player's physical limits. Each profile uses the same phrase-wide overlapping register policy: Low, Middle, or High is a hard window selected once for the complete **four-measure** phrase, never per note or bar. Notation remains an independent view of the immutable concert timeline, using Concert `+0`, B-flat `+14 semitones/+8 diatonic steps`, or E-flat `+9/+5`, with B-flat selected initially. This resolves O15 and does not imply that selecting an alto or tenor profile changes notation mode, or vice versa. On a post-generation profile switch, the system retains a phrase only if every unchanged concert event fits the new active range; otherwise it retains controls, selects a fresh seed, and regenerates the complete phrase. It never transposes source events to fit.

## Conventional compass supports a conservative shared written policy

**Cited fact:** modern commonly used alto and tenor saxophones share a conventional written compass of **B-flat3 through F-sharp6**, excluding altissimo; tenor sounds a major ninth below its written part and alto a major sixth below it ([Encyclopaedia Britannica](https://www.britannica.com/art/saxophone)). With the adopted `C4 = MIDI 60` convention, that full written compass is MIDI `58-90`, which converts exactly to concert MIDI **`44-76` for tenor** and **`49-81` for alto** ([Scientific pitch notation](https://en.wikipedia.org/wiki/Scientific_pitch_notation); [Encyclopaedia Britannica](https://www.britannica.com/art/saxophone)). These are source-backed physical/notated compass facts, not suitable first-release generator limits: the research does not establish a universal comfortable phrase range across technique, equipment, articulation, dynamic, or player level.

**Adopted product policy:** written **C4-C6** is the shared first-release saxophone working range. It is exactly two octaves, stays within the documented non-altissimo compass, and leaves the documented lower and upper edge pitches outside the generator's default vocabulary ([Saxophone range research](../../research_notes/Saxophone%20profile%20ranges/saxophone-ranges.md)). Applying the conventional sounding offsets yields tenor concert **B-flat2-B-flat4, MIDI `46-70`**, and alto concert **E-flat3-E-flat5, MIDI `51-75`**. Treat each range as inclusive integer data, so each span is 24 semitones and contains 25 legal chromatic pitches. This is a common policy shape, not a shared concert range: preserving a common written register is the musician-facing benefit, while concert MIDI remains the generator's unambiguous source representation.

| Adopted declarative profile | Active concert MIDI, inclusive | Corresponding written working range | Status and rationale |
| --- | --- | --- | --- |
| C MIDI keyboard | `48-72` | Concert display; `C3-C5` under C4 = 60 | Adopted first-release profile ([First-release specification](../first-release-master-spec.md)). |
| B-flat tenor saxophone | `46-70` | `C4-C6` when displayed as B-flat tenor | Adopted conservative first-release profile; subtract 14 semitones from written MIDI. |
| E-flat alto saxophone | `51-75` | `C4-C6` when displayed as E-flat alto | Adopted conservative first-release profile; subtract 9 semitones from written MIDI. |

## Overlapping windows preserve route for contour and recovery

**Adopted product policy:** `overlapping-three-window-v1` applies to every profile. For inclusive active endpoints `[lo, hi]`, let `W = hi - lo` and `S = max(12, ceil(W / 2))`; derive `Low = [lo, lo + S]`, `Middle = [lo + floor((W - S) / 2), lo + floor((W - S) / 2) + S]`, and `High = [hi - S, hi]`. Every adopted profile has `W = 24`, therefore `S = 12`: each register supplies 13 legal MIDI pitches and the adjacent windows overlap by seven pitch positions. This common calculation makes the range decision pure profile data rather than tenor-, alto-, or keyboard-specific planner code ([Instrument Profile](../entity_instrument_profile.atom.md); [Phrase Generation Profile Policy](../module_phrase_generation_profile_policy.atom.md)).

| Profile | Low window | Middle window | High window |
| --- | --- | --- | --- |
| C MIDI keyboard | `48-60` | `54-66` | `60-72` |
| B-flat tenor saxophone | `46-58` | `52-64` | `58-70` |
| E-flat alto saxophone | `51-63` | `57-69` | `63-75` |

**Cited fact:** Infinite Flow defines the result as one coherent four-measure object, requires range, contour, leapiness, and recovery to outrank expressive ranking, and requires the planner to reserve active range for an outward leap's required contrary recovery ([First-release specification](../first-release-master-spec.md); [Leap Recovery](../rule_leap_recovery.atom.md)). **Policy implication:** resolve `Low`, `Middle`, `High`, or `Varying` before pitch planning and apply the resolved window as a hard filter for the entire phrase. `Varying` must hash-select only from windows for which a complete legal phrase exists; it cannot change window mid-phrase, silently widen a window, waive recovery, or relax contour, grammar, cadence, or range. The overlap is essential rather than cosmetic: unlike disjoint thirds, it retains room for a phrase to approach a register boundary, make an allowed leap, and still turn back by the mandatory 1-4 semitone contrary recovery without stranding the remaining contour ([Register-window research](../../research_notes/Saxophone%20profile%20ranges/register-windows.md); [Leap Recovery](../rule_leap_recovery.atom.md)).

## Signed display transforms belong only in notation

**Cited fact:** tenor is a B-flat instrument whose written C sounds B-flat, while alto is an E-flat instrument whose written C sounds E-flat ([Yamaha](https://www.yamaha.com/en/musical_instrument_guide/saxophone/play/play003.html)). Tenor sounds a major ninth below written pitch and alto a major sixth below written pitch ([Encyclopaedia Britannica](https://www.britannica.com/art/saxophone)). MusicXML explicitly represents transposition as a written-to-sounding relationship and separates chromatic, diatonic, and octave displacement so engraving can preserve correct enharmonic spelling ([MusicXML transpose](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/transpose/); [MusicXML diatonic](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/diatonic/)).

**Adopted renderer policy:** store the following signed transforms as display-convention data and apply them only after generation. All three use treble `G2` clef; Concert `G2` is a uniform product convention for this single-staff view, not a universal concert-score assertion.

| Display convention | Concert-to-written transform | Inverse written-to-sounding interchange values | Required display behavior |
| --- | --- | --- | --- |
| Concert | `0 chromatic semitones`, `0 diatonic steps` | `chromatic=0`, `diatonic=0`, no octave change | Retain concert spelling and use `G2` under the adopted display convention. |
| B-flat tenor | **`+14 chromatic semitones`, `+8 diatonic steps`** | `chromatic=-2`, `diatonic=-1`, `octave-change=-1` | Write a major ninth above concert in `G2`; transpose notes, tonal center, key signature, chord root, and slash bass. |
| E-flat alto | **`+9 chromatic semitones`, `+5 diatonic steps`** | `chromatic=-9`, `diatonic=-5`, no octave change | Write a major sixth above concert in `G2`; transpose the same pitch-bearing notation items. |

For tenor, the inverse separates the B-flat interval from the octave because MusicXML's `chromatic` value excludes octave displacement ([MusicXML chromatic](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/chromatic/); [MusicXML octave-change](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/octave-change/)). The renderer must transpose note spelling diatonically first and then derive the accidental, which keeps examples such as concert F major as written G major for tenor and D major for alto rather than accepting a MIDI-equivalent but incorrectly spelled key ([Yamaha](https://www.yamaha.com/en/musical_instrument_guide/saxophone/play/play003.html)). Transpose a chord symbol's root and slash bass as pitch classes but preserve its quality, alterations, extensions, additions, and omissions; the tenor octave does not appear in chord-symbol text.

## Data boundaries prevent profiles from changing phrases

**Cited project rule:** a generation request consumes an explicit validated concert range and register policy, produces an immutable concert-pitch timeline, and contains no display transposition; notation then redraws that same timeline ([First-release specification](../first-release-master-spec.md); [Notation Display Preserves Phrase](../rule_notation_display_preserves_phrase.atom.md)). **Adopted implementation contract:** profile data owns `id`, `concertRange`, and the versioned register-window parameters; generation receives the resolved range/window value object and never branches on `profile.id`; notation receives the immutable timeline plus a selected display convention and never reads profile range to alter pitches. Range validation requires integer endpoints, `minMidi < maxMidi`, a span of at least 24 semitones, recognized policy version, windows contained in the active range, and intersecting adjacent windows ([Instrument Profile](../entity_instrument_profile.atom.md)).

The result preserves the four-measure contract at every boundary: a selected profile and resolved window are hard constraints on all source events, while display transformation changes no duration, measure, event ordering, concert MIDI value, harmony, seed, selected profile, or range policy. Determinism also requires a named register-resolution stream separate from melody planning, fixed candidate order `Low, Middle, High`, and persisted requested/resolved register and window data; presentation changes must never enter either seed derivation ([Seeded Phrase Reproduction](../rule_seeded_phrase_reproduction.atom.md); [Register-window research](../../research_notes/Saxophone%20profile%20ranges/register-windows.md)). The governing range atom now records the adopted profile policy, so no obsolete hard range reaches profile consumers.

**Adopted post-generation instrument-profile switching:** validate unchanged concert events against the new profile's active range. If every event fits, retain the phrase and redraw it under the selected display convention. If any event does not fit, retain current controls, select a fresh seed, and regenerate the complete phrase under the new profile. Never transpose source events to fit. This remains independent of display-mode selection. Later widening for skill, style, or player-selected variants requires a new declarative profile-data decision and player audition, not a relaxed generator constraint.

## Conclusion

Adopting the two saxophone profiles now turns a deferred range question into a small, testable data decision: the generator receives `46-70` or `51-75`, derives the corresponding fixed windows, and has no reason to know which saxophone it serves. The common written C4-C6 target is the key product simplification: it makes the default vocabulary familiar to both saxophonists without sacrificing concert-pitch determinism or forcing a false common sounding range.

The stronger architectural result is that an alto phrase can be displayed in B-flat notation, a keyboard phrase can be displayed in E-flat notation, and every one remains exactly the same four-measure concert phrase. That decoupling prevents display preferences from becoming hidden playability or generation settings, while leaving future physical-range expansion available for deliberate, separately tested decisions.
