# Notation Note Identity and Score Overlays

## INTENT
Let the practice session point at notes of the engraved score (the starting note, the notes already acknowledged) and at the measure being played, by naming each written note with the same identity the acknowledgement uses, and drawing those overlays on the engraved score without changing the score itself.

## THE RULE / LOGIC
Note identity. A note's identity is the acknowledgement's ExpectedNoteIdentity: the phrase number (1-based), the measure index, and the event index, which is the attack's index among that measure's concert events, rests included. The notation layer reuses that type and does not define a parallel one.

Glyph resolution. A pure function resolves every written glyph of a written phrase to the identity of the attack it sounds as. A glyph that starts a fresh attack takes its measure index and its source event index. A glyph tied from the previous glyph (a notation split inside a measure, or a tie continuation across a barline or a system break) takes the identity of the attack it continues. A rest has no identity. A phrase number that is not a positive integer, or a tied glyph whose previous glyph is not a note tied to it, is a caller error: it throws a typed error before anything is cleared or drawn.

Engraving tags. The engraver tags each note glyph's own parts in the SVG with the identity of the attack it sounds as, so a tie continuation's parts carry its attack's identity: notehead, stem (a beamed note's stem included, even though it is drawn inside the beam's group), flag, accidental and augmentation dot. Beams, ledger lines, ties and chord symbols carry no identity, so they keep the staff's ink when a note is acknowledged; an attack's chord symbol is only marked as belonging to that attack, for placing the start marker. The engraver also records each measure's playhead band rectangle: horizontally from the measure's opening barline (on a system's first measure, from where its notes start, after the clef, key and time signatures) to its closing barline; vertically one span shared by every measure of the system. Tagging changes no pixel of the idle rendering.

Overlays. A DOM-only overlay step, with no engraving library involved, applies an overlay state to the engraved SVGs. The state has three parts: a start marker (an identity, or none), a playhead measure (a measure index, or none), and a list of acknowledged identities. A state replaces the one applied before, so applying the same state twice gives the same result. Every identity and measure the state names is checked before anything changes: one the engraved phrase lacks (a rest, another phrase number, an index past the measure's events, a tie continuation's own index, a measure the score does not draw) throws a typed error and leaves the score as it was. The start marker is a downward-pointing triangle 1.2 staff spaces wide and 1 tall, centred on its notehead and drawn over every glyph. Its reference edge is the higher of the note's own ink (its tagged parts, its ledger lines and the beam on its stem) and the staff's top line. Its apex sits half a space above that edge, between the note and the note's chord symbol, only when the gap from that edge up to the chord symbol is at least 2 spaces; otherwise its apex sits half a space above the chord symbol's top. The chord symbol never moves, and the marker stays inside the top of the system. The playhead is one band rectangle drawn behind every glyph of its measure's system. Acknowledging a note adds the note-ack class to every part carrying its identity, in every system, which only recolours them, so a tie continuation lights with its attack. No overlay change is animated.

Phrase score. The phrase score component takes the phrase number and the overlay state as inputs, with no overlays by default. It draws the state onto the engraved systems after every successful engraving and whenever the state changes, without re-engraving, so a re-engrave keeps the overlays. While the score on screen is an older phrase or phrase number (the new one is waiting for its engraving, as when both inputs change in the same tick), it draws nothing on that score; the engraving that swaps in the new score draws the state current at that moment. The idle workspace score is phrase 1. While the phrase score shows a running session, it does not apply the given state as it is: each phrase on screen gets its own state, applied to that phrase's systems only and never to a system fading out, with no start marker, the playhead band only on the phrase that owns the playhead, and only those of the given acknowledged identities that the phrase's systems on screen draw, so a note of a part not on screen is left out rather than rejected.

Pitch-free inputs. Overlay inputs are identities and a measure index only; none carries a pitch, so no overlay can draw a note that is not in the phrase.

Out of scope. Deciding when the start marker shows, when the playhead band steps, and which notes are matched is not this module's job (during a session the rolling display decides the band and that no start marker shows); in tests, the notation harness drives the overlays.

## TECHNICAL INTERFACE
src/notation/note-identity.ts: resolveGlyphIdentities(phrase, phraseNumber) gives the ExpectedNoteIdentity of each written glyph, measure by measure, or null for a rest; noteIdentityKey(identity) writes it as "<phraseNumber>:<measureIndex>:<eventIndex>"; failures throw NoteIdentityError. src/notation/vexflow-mapping.ts describeNoteParts reports where a drawn glyph's own parts are; src/notation/note-part-tags.ts tagSystemNoteParts writes data-note-id and data-note-part (notehead, stem, flag, accidental, dot) on those parts, wrapping bare glyph texts in an attribute-less group, and data-chord-for on an attack's chord symbols. engraveWrittenPhrase(targets, phrase, phraseNumber, containerWidthPx, viewport) tags every system and records data-band-x, data-band-y, data-band-width and data-band-height on each g.measure-slot. src/notation/score-overlay-state.ts holds the state, ScoreOverlays { startMarker: ExpectedNoteIdentity | null, playheadMeasure: MeasureIndex | null, acknowledged: ExpectedNoteIdentity[] }, and NO_SCORE_OVERLAYS, the idle state. src/notation/score-overlays.ts: applyScoreOverlays(svgs, phraseNumber, overlays) applies a state, drawing path.start-note-marker, rect.playhead-band and the note-ack class; a name the engraved phrase lacks throws ScoreOverlayError; this drawing code loads on demand with the engraver, through src/components/notation/load-staff-drawing.ts, which PhraseScore waits for before it engraves. PhraseScore: props phrase, phraseNumber (required), overlays (optional, NO_SCORE_OVERLAYS by default) and session (optional, null by default); with a session, only overlays.acknowledged is read, and src/components/notation/session-staff.ts sessionPhraseOverlays(phraseNumber, playhead, acknowledged) builds each phrase's state, which src/components/notation/session-staff-marks.ts drawSessionMarks applies per phrase after filtering the acknowledged identities to the glyphs its systems on screen carry.

## EXPECTATION
Every written glyph of a phrase resolves to the identity of the attack it sounds as: fresh attacks to their own measure and source event index, tied continuations (within a measure, across a barline, across a system break) to their attack, rests to none; an invalid phrase number or a malformed tie throws a typed error. Only notehead, stem, flag, accidental and augmentation dot carry an identity, tie continuations' parts carrying their attack's, and the idle rendering is pixel-identical with or without tags. Each measure records one band rectangle, one vertical span per system. Applying an overlay state is idempotent, draws at most one start marker, sized and placed from the drawn ink as the rule states and inside the top of the system, draws one playhead band behind the chosen measure's system, and recolours only the acknowledged identities' tagged parts, never beams, ledger lines, ties or chord symbols. An identity or measure outside the engraved phrase throws a typed error and changes nothing, and no overlay input can introduce a pitch. A re-engrave keeps the current overlays, and when a new phrase or phrase number arrives with a new state, the state lands on the new score, never on the old one. During a session, no start marker is drawn, the band shows only on the playhead's phrase, and an acknowledged note not drawn on screen is skipped without error.
