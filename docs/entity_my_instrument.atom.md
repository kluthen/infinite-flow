# My Instrument

## INTENT
Represent the player's own instrument as one saved record from which a valid instrument profile is derived, named by a fixed id kept apart from its display name.

## THE RULE / LOGIC
My instrument is one saved record, from which a validated instrument profile is derived.

Identity. Its id is the fixed literal `my-instrument`, one member of the instrument-profile id set alongside the three built-in ids. Saved settings, kept sessions and replay keys store that id, and it is never renamed. The display name is a separate, non-empty property the player may change at any time; it is never part of the id and never affects generation: two my instruments that differ only by display name generate the same phrase for the same request and seed.

Record. The record holds the id `my-instrument`; the template, the built-in profile id it was made from, to which the instrument control returns when my instrument is deleted; the display name; the clef (below); the written range, its lowest and highest written note as whole numbers, which is what the player sets and keeps; the transposition, as a number of octaves (a whole number from 0 up), a number of semitones (a whole number from 0 to 11) and one direction for the whole transposition, octaves included: lower, same or higher, as a written note sounds lower than written, at the same pitch, or higher; and the input kind, "MIDI controller", the only kind, stored so that a microphone kind can be added later without changing the record's shape. The direction is "same" exactly when octaves and semitones are both 0; a non-zero size always has lower or higher.

Clef. My instrument's clef is treble or bass, the clef its written part is drawn in, as the player chooses. The clef is display only: it is not part of the generator-facing profile, the generation controls or the generation intent, so two my instruments that differ only by clef generate the same phrase for the same request and seed. A phrase written for my instrument is drawn in my instrument's clef, which the written phrase carries. The built-in profiles have no clef choice: they are always written in treble clef.

Derived, never entered. The transposition's size is 12 semitones per octave plus the semitones. The concert (sounding) range is the written range moved by that size in the transposition's direction: lower makes it sound lower. The interval name and letter-name steps come from a fixed table on the semitones: 0 unison (with octaves, one or more octaves), 1 minor second, 2 major second, 3 minor third, 4 major third, 5 perfect fourth, 6 augmented fourth, 7 perfect fifth, 8 minor sixth, 9 major sixth, 10 minor seventh, 11 major seventh, with letter-name steps 0, 1, 1, 2, 2, 3, 3, 4, 5, 5, 6, 6; each octave adds 12 semitones and 7 steps, so 1 octave and 2 semitones lower is a major ninth lower, 8 steps, the tenor saxophone's. The generator-facing instrument profile carries the concert range, the built-in profiles' register-window policy and window derivation algorithm, the chromatic/diatonic transposition pair with written = concert + chromatic (so "lower" gives positive chromatic and diatonic counts, "higher" negative ones), and the my-instrument display name.

Validity. Building my instrument refuses, with a reason, and never clamps: endpoints that are not whole numbers; a lowest written note not below the highest; a span under 24 semitones; a written range outside its clef's bound, both ends included: written C2 to C7 (MIDI notes 36 to 96) in treble clef, written E0 to E5 (MIDI notes 16 to 76) in bass clef, the reason naming the clef and the notes out of bound; a concert end outside MIDI notes 0 to 127 (the octaves have no bound but this one); a malformed transposition, being negative octaves, semitones outside 0 to 11, or a direction inconsistent with the size. A change of clef alone checks the range again, so the same written range may be valid in one clef and refused in the other.

Its kept sessions. Every kept session names, by id, the instrument it was played with; those naming `my-instrument` are my instrument's, and only they are ever touched by a change to it, the built-in profiles never changing. Deleting my instrument deletes them all, with their favorites, comments and played notes. Saving a change to its written range or its transposition erases them the same way, after a warning; with none, nothing is erased and no warning is shown. A change of its display name or its clef keeps them, with no warning, since nothing generated changes; each kept phrase keeps the clef it was played in. So every kept session of my instrument was played with the written range and transposition it has now.

Carriage. The profile travels as data beside the generation controls, which name the instrument by id only. When the controls name `my-instrument`, the generation intent is given the my-instrument profile as data, and refuses a missing one or one whose id is not `my-instrument`; a built-in id still resolves from the built-in table, and a profile supplied for a built-in id is refused. A built-in template turned into my instrument without change gives the built-in's profile (concert range, window policy, derived windows and transposition), differing only in id and display name.

## TECHNICAL INTERFACE
`src/domain/profile/my-instrument.ts` exports `makeMyInstrument({ template, name, clef, writtenRange, transposition })`, which returns the validated, deep-frozen `MyInstrument` (id, template, display name, clef, written range, transposition, input kind `midi-controller`, the derived interval and the generator-facing `profile`) or throws `MyInstrumentError` carrying the refusal's reason code; `findMyInstrumentRefusal(input)`, which returns the first refusal (`MyInstrumentRefusal { reason, message }`) without throwing, checked in a fixed order: a blank name, a template that names no built-in, a malformed transposition, non-whole endpoints, then the range limits (the two-octave span, and, once chunk 20 builds it, the clef's bound); and `myInstrumentDraftFromTemplate(templateId)`, a built-in's written range and transposition as a starting point, with no clef. `src/domain/profile/instrument-clef.ts` holds the clef: `InstrumentClef` (`treble` or `bass`), `INSTRUMENT_CLEFS`, `isInstrumentClef(value)`, and `BUILT_IN_INSTRUMENT_CLEF` (`treble`), every built-in profile's clef and the clef a new my instrument starts in from its template; `makeMyInstrument` takes the clef as typed and keeps it as given, adding no refusal of its own. `src/domain/profile/transposition-interval.ts` holds the transposition (octaves, semitones, direction), its validation and the interval table (`deriveTranspositionInterval`, `instrumentTranspositionFor` and its inverse `transpositionFromInstrumentTransposition`). `src/domain/profile/instrument-profiles.ts` exports `MY_INSTRUMENT_ID` and the id set `InstrumentProfileId`, the three built-ins and `my-instrument`; `INSTRUMENT_PROFILE_IDS` stays the three built-ins. The generation controls accept the four ids (`ACCEPTED_INSTRUMENT_PROFILE_IDS` in `src/domain/controls/generation-controls.ts`), and the generation intent (`resolveInstrumentProfile` in `src/domain/generation/generation-intent.ts`) receives the my-instrument profile as data beside them. Until my instrument travels through the worker and the session, the paths that rebuild an intent from the controls alone (the session's attempt intents, the carry-in receiver, the worker's inbound message) refuse `my-instrument`. The clef, `treble` or `bass`, sits on the `MyInstrument` value (and on `MyInstrumentInput`) beside the display name, outside its `profile`, so neither the generation controls, the generation intent nor the worker's messages carry it; the written phrase carries it as it carries its written range.

## EXPECTATION
- My instrument's id is `my-instrument` whatever its display name; two my instruments differing only by display name generate the same phrase for the same request and seed.
- Two my instruments differing only by clef generate the same phrase for the same request and seed; the generator-facing profile carries no clef.
- A written span of 23 semitones, or a lowest note not below the highest, is refused with its reason; a span of 24 is accepted.
- A written range outside its clef's bound (below C2 or above C7 in treble clef, below E0 or above E5 in bass clef) is refused with its reason; C2 to C7 in treble clef and E0 to E5 in bass clef are accepted; a range valid in one clef is refused after a change to a clef whose bound it leaves.
- Non-whole endpoints, a concert end outside MIDI notes 0 to 127, or a malformed transposition is refused with its reason, never clamped.
- Every transposition from 0 to 11 semitones, with and without octaves, in each direction, derives the table's interval name and letter-name steps; 6 semitones is an augmented fourth; 1 octave and 2 semitones lower is a major ninth lower, 8 steps, chromatic +14 and diatonic +8.
- Changing the transposition keeps the written range and moves the concert range.
- Each built-in template turned into my instrument without change gives the built-in's profile, derived windows included, differing only in id and display name.
- The generation intent refuses a missing my-instrument profile, a profile whose id is not `my-instrument`, and a profile supplied for a built-in id.
- Deleting my instrument deletes every kept session played with it and no other; saving a change to its written range or transposition erases them after a warning; a change of its display name or clef keeps them.
