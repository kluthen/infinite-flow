# Idle Generation Session

## INTENT
Coordinate the active phrase workspace at Idle as root-created, readonly in-memory session state: its controls, its generation and notation outcomes, and the actions that change them.

## THE RULE / LOGIC
A root-created Vue composable owns pending controls, current generation intent and result, presentation state kept separate from generation state, operation state, the "staff needs more room" notice state, and retryable error state for the active browser session. It exposes explicit control, profile, theme, notation, Generate, Regenerate, retry-generation, and retry-notation actions. Outside the room notice, ordinary control, figure-level, preset choice, theme, and notation edits never generate; an instrument-profile switch while a phrase is shown regenerates it. Under the room notice, an edit to a setting the phrase is generated from (tempo, the audio mix, the theme and notation edits excluded) reacts to it as the Idle fit round defines: under the too-many-notes cause it starts a retry round, an instrument-profile switch included; under the no-room cause it runs the phrase-independent room check, which can clear the notice into a new phrase, while an instrument-profile switch only changes the selection. Generate and Regenerate coordinate injected seed, request-identity, generation-outcome, fit-check, room-check, and notation-outcome seams; Regenerate retains pending controls and requests a new seed.

Every Idle generation -- Generate, Regenerate, Retry-generation, the regeneration an instrument-profile switch runs, and the runs the room notice and a phrase left too wide start by themselves -- is one fit run: one operation that may span several generation attempts, the first plus up to three fresh-seed retries, each with its own fresh seed and request identity, checked against the staff's room before anything is drawn. Each phrase a fit run publishes comes with one session seed, drawn from its own injected session-seed provider, apart from the phrase seeds' provider, once per publishing run however many attempts it made; the Idle result carries it, and a session started from that phrase 1 derives every later seed from it. The Idle result also records the settings its fit run was built from: the controls as the player chose them, the figure levels and the preset selection. It takes the chosen controls, not the intent's, since the intent holds the note density the window's width gave, which is not a setting. Later edits change the current controls, never the recorded settings, so whether the phrase on screen is stale is read by comparing the two by value, and a session started from that phrase 1 carries them as the settings phrase 1 was generated under. A staff layout failure (no room for the staff, or notes too wide for it) is never a retryable notation error: it goes to the room notice, to a replacement run, or, under a blocked rhythm-settings combination, to no phrase; only other notation failures are retryable notation errors.

At most one operation runs at a time, a fit run counting as one operation however many attempts it makes. A background pre-generation attempt at Idle is not an operation of this composable: it sets no operation state, locks no edit, and never makes Start wait. The generation seam the root injects yields to the player first: before each request the composable posts, it aborts the background attempt in flight, if any, so a player request never waits behind background work, and the composable's own requests still carry no abort signal and are never cancelled. During an operation consumers can read but cannot mutate the exposed state, with one exception: the preset-list action, which replaces the player presets the composable lists and, where the preset rules say, the preset selection, checks no operation, so the preset actions work while a phrase is being generated or drawn (Loading). It changes no generation setting and starts no generation. Whether a session is running is not this composable's to know: the player presets composable refuses every preset action while one runs. The composable coordinates outcomes without implementing Step 5 through Step 9 planners, engraving, or components, and uses no storage itself. Its controls, figure levels, preset selection and theme, and the player presets it lists after the built-ins, start from the settings the root gives it, the player's saved ones loaded before the first draw (the first-visit values when none are given); after that, only the preset-list action replaces the player presets. Each control, figure-level, preset choice, instrument-profile or theme action that applies saves exactly the settings it changed through an injected saver; these actions are the player's change handlers' way in, so nothing the app changes by itself is saved.

The composable also listens to the staff's layout reports: at Idle, a change of the staff's layout inputs can clear the room notice into a new phrase, start a retry round under it, give the notice its no-room cause, have a phrase on screen that no longer fits replaced by a new one, or give way to no phrase under a blocked combination. The composable stops listening for crossings and for layout reports when the workspace is torn down.

## TECHNICAL INTERFACE
The root creates the composable with the initial settings (initialSettings: controls, figure levels, preset selection, player presets, theme and my instrument), a saveSettings seam, and injected seed, session-seed (`nextSessionSeed`, with `withSessionSeed` joining a published phrase to its session seed), request-identity, window-width, generation, and notation outcome seams, (the generation seam being the root's `yieldingToPlayer(slot, generate)` from `src/composables/generation-session-pregeneration.ts`, which calls the Idle background slot's `yieldToPlayer()` before posting each request), plus a fit check (does a generated phrase fit the staff's current layout inputs, drawing nothing), a room check (does the staff have room at all with a given key signature), the staff's layout-input reports, and a required seam that drops whatever the notation seam presents. Consumers receive readonly pending-control, note-density context (where the window stands against the tablet-landscape layout's width, and whether the density has stepped down, always false at Idle), intent/result (the workspace result carrying its session seed, `WorkspaceSessionResult.sessionSeed`, and the settings its fit run was built from, `settings`, an `IdlePhraseSettings { controls, figureLevels, selection }` in `src/composables/workspace-session-result.ts`, the chosen controls, the levels and the selection read as each request is posted), presentation, operation, and error state, the room notice's cause (no room, notes too wide, or none), whether retries are running, and a room-notice announcement count, plus explicit actions (among them startFreshPhrase, the fresh run a session end asks for, and the preset-list action, which replaces the player presets and, when given one, the preset selection, and checks no operation) and a teardown that stops listening for window-width crossings and layout reports; no storage API is part of the interface.

## EXPECTATION
Consumers cannot mutate workspace state directly. Outside the room notice, ordinary edits produce no generation request; under it, only an edit to a setting the phrase is generated from can start a run, as the Idle fit round defines. Generate and Regenerate each start one fit run through injected seams, one operation of up to four attempts issued one intent at a time. A regenerate operation preserves controls and uses a renewed seed. A staff layout failure never shows the retryable notation error. Reloading or a later browser session restores no intent, result, operation state, room notice, or error; the controls, the figure levels, the preset selection and the theme start from the settings the root gives, and each action that applies saves the settings it changed. The room notice's cause, whether retries are running and the announcement count are readonly. Each published Idle result records the chosen controls, the figure levels and the preset selection its fit run was built from, the player's chosen note density rather than the one the window's width gave; an edit made afterwards changes the current controls, never the recorded settings. A background pre-generation attempt running at Idle changes no operation state and locks no edit; each request the composable posts first aborts it, and is itself never cancelled. The preset-list action applies during an operation as at rest; it changes no generation setting, starts no generation, and replaces only the player presets and, when given one, the selection.
