# Generation Request Construction

## INTENT

Construct one outer generation intent from normalized generation controls only when the player explicitly requests generation.

## THE RULE / LOGIC
The GenerationIntent factory constructs an outer request boundary from normalized generation-only controls, the seven figure levels, the Seventh chords level, the selected instrument-profile policy, player register intent including unresolved Varying, an injected seed, and an injected request identity. The intent carries the figure levels as figureLevels, from which the generator reads what it may write, and no musical profile's or preset's name: the factory's input holds the levels themselves, the Idle session's own, and the preset selection never reaches the factory or the intent. Regeneration keeps the previous intent's levels, and the generation worker's rebuild and the replay key's decoder build from the levels they read. The intent carries the Seventh chords level as chordFamilies, which names each chord family by its capability id with that family's level, never by a preset's or profile's name: one family, seventh-chords, whose level is off, sometimes, favored or stronglyFavored, ids the interface maps to its own labels. It is a setting of its own beside the figure levels, not the allowance the figure levels give (module_musical_profile_capabilities), and it stays outside the generation controls, so the replay key's control order, the sweep's dimensions and the control catalog are unchanged; the resolved GenerationRequest, which holds neither the controls nor the figure levels, does not repeat it. Every intent holds it: the factory requires it, regeneration and the carry-in intent keep the level they are given, every intent built from settings takes the level those settings hold: the Idle session's from the Idle state, and the session's attempts on every rung from the session's settings, frozen at Start; a fresh Jam's phrase-1 rungs are given Off, since no Jam state holds a level yet, and so is the rhythm prewarm's, the level shaping no rhythm; and an input from before v3.3, a replay key up to `ifk4.` or a kept phrase's stored intent, reads Off where it is decoded. Generation reads it to place the seventh chords (service_generation_orchestration); at Off it changes no phrase. Theme, browser capability state, mutable workspace session state, audio state, UI state, and prior results are structurally excluded, except the carry-in the session phrase before hands forward, which the factory checks against the intent. The intent may also hold two optional groups, the rhythm lock group and the steering block, each a value its own validating constructor built, kept as given after the carry-in, in that order; a carry-in from no phrase is accepted only beside a steering block. Without them the intent is the one built before v3.2, apart from its chordFamilies. The session's attempts carry the rhythm lock group while the lock is on and the steering block in a steered session, and a fresh Jam's phrase-1 rungs carry them as their rung gives. The note density in the controls the factory receives is the density the phrase is generated with, which can differ from the chosen one: the caller resolves the chosen density when the request is made, from whether the window is below the tablet-landscape layout's width and, during a session, whether that session has stepped its density down, and passes the plain result. The window's width reaches the intent only through that resolved density, never as browser state, and the chosen density itself is left unchanged. Generate, Regenerate, Retry generation, and the regeneration an instrument-profile switch runs while a phrase is shown are the only actions that invoke the factory; each retains the current controls, figure levels and Seventh chords level while using a renewed injected seed and request identity, including Retry generation after a failure, which builds this same fresh intent from the current controls rather than replaying the failed one unchanged. The resolved GenerationRequest is unchanged apart from carrying that carry-in and those groups unchanged. Step 7 orchestration, not this factory, owns Varying feasibility and planner-facing resolution.

## TECHNICAL INTERFACE
Generate, Regenerate, Retry generation, and the regeneration an instrument-profile switch runs supply normalized catalog controls, with the note density resolved for the window's width at that moment, the figure levels, the Seventh chords level, the selected instrument-profile policy, an injected seed, and an injected request identity to makeGenerationIntent (src/domain/generation/generation-intent.ts), whose input, GenerationIntentInput { requestId, seed, controls, figureLevels, chordFamilies, instrumentProfile?, rhythmLock?, steering? }, holds the levels, read through parseFigureLevels and parseChordFamilies; it has no musical-profile variant. src/domain/chords/chord-families.ts holds the family id seventh-chords (CHORD_FAMILY_IDS), the four level ids off, sometimes, favored and stronglyFavored (CHORD_FAMILY_LEVEL_IDS), the types ChordFamilies and ChordFamilyLevel, OFF_CHORD_FAMILIES, isOffChordFamilies, and parseChordFamilies, which accepts exactly the known family ids, each at a known level, and no extra field, and otherwise throws a ChordFamiliesError. The Idle session's intents (freshIntentFromControls, src/composables/use-generation-session.ts) pass the Idle state's chordFamilies, and the session's buildAttemptIntent (src/session/session-intents.ts) the session settings' chordFamilies; the rhythm prewarm's (src/composables/generation-session-prewarm.ts) and a fresh Jam's jamAttempt (src/jam/jam-phrase-one-attempts.ts) pass OFF_CHORD_FAMILIES, and a fresh Jam's session settings hold it (freshJamSettings, src/jam/fresh-jam-settings.ts); makeCarryInGenerationIntent (src/domain/generation/carry-in/carry-in-intent.ts) keeps the level its input gives. regenerateGenerationIntent builds from the previous intent's controls, figureLevels and chordFamilies with a fresh injected seed and request identity, handing on its rhythm lock group and steering block unchanged; the GenerationIntent it produces holds the levels in its figureLevels field, the Seventh chords level in its chordFamilies field, and no musical profile. Consumers receive GenerationIntent separately from presentation state; core planners continue to accept only the existing resolved GenerationRequest.

## EXPECTATION
Changing presentation, browser, session, audio, or UI state cannot alter or construct GenerationIntent, except that the note density a newly built intent carries is the one the window's width (and, during a session, the session's step-down) gives at the moment it is built; a crossing of that width never builds an intent or alters one already built. Every emitted intent has normalized generation controls, exactly the seven figure levels, a Seventh chords level for exactly the known chord families, one selected profile policy, one register intent, one seed, and one request identity, and holds no musical profile's or preset's name. An intent carries exactly the levels it was built from, whatever the preset selection. Every intent the app builds carries the Seventh chords level of the settings it is built from, a Jam's at Off, and the request resolved from it is byte for byte the one resolved before the level existed. An unresolved Varying selection never reaches the existing resolved GenerationRequest through this factory. An intent built without the rhythm lock group and the steering block has neither key and, its chordFamilies apart, is exactly the intent built before v3.2; the request resolved from it is exactly the one resolved before v3.2.
