# Workspace Session Flow

## INTENT
Coordinate the active phrase workspace as root-created, readonly in-memory session state.

## THE RULE / LOGIC
A root-created Vue composable owns pending controls, current generation intent and result, presentation state kept separate from generation state, operation state, and retryable error state for the active browser session. It exposes explicit control, profile, theme, notation, Generate, Regenerate, retry-generation, and retry-notation actions. Ordinary control, musical-profile, theme, and notation edits never generate; an instrument-profile switch while a phrase is shown regenerates it. Generate and Regenerate coordinate injected seed, request-identity, generation-outcome, and notation-outcome seams; Regenerate retains pending controls and requests a new seed. Retry-generation is available only while idle with a captured generation error present; it does not require a retained failed intent. It builds a brand-new intent from the current controls and profile with a fresh injected seed and request identity -- the same construction Generate and Regenerate use -- rather than replaying the failed intent unchanged, so an edit made after the failure and before retrying is picked up; it applies the same unsupported-rhythm-settings block as Generate and Regenerate. A captured generation error is cleared when the next generation attempt starts, whether Generate, Regenerate, Retry-generation, or the regeneration an instrument-profile switch runs while a phrase is shown; it is also cleared, along with the phrase, when an instrument-profile switch made while a phrase is shown clears that phrase instead of regenerating it because the switched controls are an unsupported rhythm combination. It is unaffected by ordinary control, musical-profile, theme, or notation edits made while idle after the failure, and by an instrument-profile switch made while no phrase is shown, which only changes the selection. At most one generation or notation operation runs at a time. During an operation consumers can read but cannot mutate the exposed state. The composable coordinates outcomes without implementing Step 5 through Step 9 planners, engraving, or components, and never persists or restores user or session state.

The root also injects a window-width seam that tells whether the window is below the tablet-landscape layout's width. Generate, Regenerate, Retry-generation, and the regeneration an instrument-profile switch runs each read that seam when they build their intent, and build it with the note density the width gives at that moment, while the pending controls keep the chosen density. The unsupported-rhythm-settings block is judged on that same density at the moment the action is taken. The composable mirrors each crossing of that width in readonly state so the controls and the block follow the window at Idle; a crossing never generates, regenerates, or changes the phrase on screen. The composable stops listening for crossings when the workspace is torn down.

The workspace composition root takes an injectable prewarm policy, enabled in production and disableable for tests and measurements. While it is enabled, the workspace posts a prewarm to the generation worker for the current controls, with the note density the window's width gives at that moment, when the generation worker starts, again after any rhythm control changes, including a profile switch that changes a rhythm control, and again after a crossing of the window's width that changes the note density that width gives. Prewarms are deduplicated by the resolved rhythm setting: one is posted only when that setting differs from the last one posted, so a non-rhythm edit, or a crossing that leaves the resolved density unchanged, posts none. Every prewarm carries one fixed seed and one fixed request identity and never draws from the injected seed or request-identity providers, so the seeds and request identities generation attempts receive are the same as with prewarm disabled. A prewarm is not a generation attempt: it gets no response and changes no phrase, intent, result, operation, or error state. Idle and a running session share the one generation worker, so both benefit from it.

## TECHNICAL INTERFACE
The root creates the composable with injected seed, request-identity, window-width, generation, and notation outcome seams. Consumers receive readonly pending-control, note-density context (where the window stands against the tablet-landscape layout's width, and whether the density has stepped down, always false at Idle), intent/result, presentation, operation, and error state, plus explicit actions and a teardown that stops listening for window-width crossings; no storage API is part of the interface. The workspace session also exposes createSessionRunner({ start, checkFit, now, onOutput, onError }), which starts a session runner from the given session start, fit check, audio clock, and output and error sinks, bound to the same generation seam, seed and request-identity providers, and window-width seam the Idle flow uses, so a running session and the Idle flow share the app's one generation worker. The workspace composition root also takes an injectable prewarm policy, enabled by default in production, which tests and measurements can disable.

## EXPECTATION
Consumers cannot mutate workspace state directly. Ordinary edits produce no generation request, while Generate and Regenerate issue one intent at a time through injected seams. A regenerate operation preserves controls and uses a renewed seed. Retry generation is available only while idle after a captured generation error, is blocked under an unsupported rhythm setting exactly like Generate and Regenerate, and issues a brand-new intent built from the current controls and profile with a fresh seed and request identity rather than replaying the failed attempt, so a control edit made after the failure and before retrying is reflected in the retried request. The captured generation error remains visible through any control, musical-profile, theme, or notation edit made while idle, and through an instrument-profile switch made while no phrase is shown; it clears once the next Generate, Regenerate, or Retry-generation attempt begins, or when an instrument-profile switch made while a phrase is shown either starts its regeneration or, under an unsupported rhythm combination, clears the phrase without generating. Reloading or a later browser session restores no controls, intent, result, presentation preference, operation state, or error. Every intent carries the note density the window's width gave when it was built. A crossing of that width updates the readonly note-density context and never issues a generation request or changes the phrase on screen. With the prewarm policy enabled, the generation worker's start and each change of the width-resolved rhythm setting, whether by a rhythm control change, a profile switch that changes one, or a width crossing that changes the resolved note density, post exactly one prewarm for the current width-resolved controls, and no other edit or crossing posts one; with it disabled no prewarm is posted. A prewarm never issues a generation request, changes the phrase on screen, or consumes a seed or request identity from the injected providers.
