# Infinite Flow v3.4 release notes

Version 3.4.0, dated 2026-11-23; the `3.4.0` tag follows the owner's go only (spec D550, D556). The
release gate below is its automated part, run on branch `v3.4-w3` before it merges. One item of the
definition of done is open: H1, the owner seeing the lexicon page
([§E15](../../specs/versions/v3/master-spec.md#e15-definition-of-done) item 18), the owner's hand
check before the tag's go ([Hand checks](#hand-checks)).

## What v3.4 is

v3.4 has two parts: the lexicon page, and the refactors the structural review took. The guiding
principle is unchanged: the app acknowledges and encourages, and never grades or scores the player.

- **The lexicon page.** A "Lexicon" button in the footer, after "Your data", opens a full-window
  page listing every shown word of the project's lexicon (`docs/music/lexicon.md`, v1.9: 334
  entries, 323 shown, 11 Internal), A to Z under its letter and by search. Each entry shows its
  word, group, plain line and other names, and behind More its definition, its meaning in the app
  under "In Infinite Flow" and its related words as links. The search matches the word and its
  other names, ignoring case, accents, hyphens, apostrophes and spaces, in five tiers, and lists
  apart the words whose plain line mentions the query. The page is disabled during a session,
  opens in any orientation, works offline after one visit, and is reached at `#lexicon` in the
  browser's history. Its code and its words load on the first opening, never in the first load.
- **One source.** The lexicon file is the only source: the build reads it, fails on a malformed or
  empty lexicon naming the entry's word and line, and writes the shown entries into a words' file
  of their own. No copy of the words is committed.
- **The lexicon API.** The page reads the lexicon only through a read interface in `src/lexicon/`,
  with no DOM, browser storage, Vite-only import or network use; the entry contract has a JSON
  Schema beside the module ([`docs/lexicon-api.md`](../lexicon-api.md)). It lives in this app
  (spec D574).
- **The structural review and its refactors.** A read-only review of the code's fitness for v4.0
  ([report](../../specs/versions/v3/structural-review-report.md)), whose four taken refactors are
  built: a test file above 10 atoms now warns rather than fails (R4); the library line is enforced
  by `verify:boundaries` and a no-DOM type project over `src/domain/` (R1); `src/session/` imports
  only itself and the library set (R2); the Jam host wiring moved out of `WorkspaceShell.vue`
  into `use-jam-host.ts` (R3), the shell from 596 to 475 effective lines.

v3.4 is [Part E](../../specs/versions/v3/master-spec.md#part-e--v34) of the v3 master spec, built
by the [v3.4 build plan](../../specs/versions/v3/build-plan-v3.4.md) in three waves; every figure
and commit is in the [wave log](../../specs/versions/v3/wave-log-v3.4.md).

## How to read the table

The table below has one row per item of
[master spec §E15](../../specs/versions/v3/master-spec.md#e15-definition-of-done), in its order:
items 1 to 18.

- **Criterion:** the number and a short paraphrase. The spec's wording is the reference.
- **Evidence:** as `file` › 'test title'. A title with `${...}` or `$name` is a parameterized test,
  quoted as written in the source; a test inside a `describe` is named by its own title. A check
  that is not a test is written out in the row. The evidence named is a sample of the strongest
  tests, not every test.
- **Run by:** the npm script that runs the evidence.
- **Status:**
  - **Verified:** automated tests check it, and they pass.
  - **Verified + measured:** a measurement's figure is recorded as well (item 13).
  - **Verified, thin:** part of the item rests on a written check or on how the code is built, not
    on a test; the row names that part.
  - **Verified, record:** a check of the declared-intent record, not a test (item 17).
  - **Open:** H1, the owner's hand check before the tag (item 18).

The decisions cited as "spec Dn" are in [specs/decisions.md](../../specs/decisions.md), those cited
as "ux Dn" in [ui_ux/decisions.md](../../ui_ux/decisions.md).

## Gate commands

- `npm run quality` runs every automated gate, in order: `format:check`, `lint`, `lint:links`,
  `lint:health`, `test:unit`, `build`, `verify:boundaries`, `test:e2e`, `test:e2e:pregeneration`
  (the same e2e list again, with pre-generation on), `test:a11y`, `test:notation`, `atd:lint`,
  `atd:check`. Every **Verified** row rests on it. v3.4 adds the lexicon's two end-to-end specs to
  `test:e2e` and `tests/e2e/accessibility-lexicon.spec.ts` to `test:a11y`.
- `npm run lint:links` checks every relative Markdown link and `#heading` anchor in the repo,
  offline; it is part of `npm run quality`.
- `npm run verify:boundaries`, after `npm run build`, checks the start-up JavaScript budget, the
  per-chunk budgets and the words' file budget, that no `src/jam/` module and no module of the
  lexicon page, its API or its words is in the first load, and, from v3.4's waves 2 and 3, the
  library line and `src/session/`'s one-way rule over the source.
- Results at the wave gates, each green (`npm run quality`, exit 0), recorded in the
  [wave log](../../specs/versions/v3/wave-log-v3.4.md):
  - wave 1, on a1660fd9+8dc07f95, the driver's machine: unit 10,325 tests in 668 files; e2e 786
    passed in each lane; a11y 86; notation 121;
  - wave 2, on 025e93b7, 2026-11-23 20:36–20:47 CET, AMD Ryzen 5 PRO 8640HS, idle: unit 10,344
    tests in 668 files; e2e 786 ×2 (1 skipped); a11y 86; notation 121 (4 skipped);
  - wave 3, on 83f00256, 2026-11-23 21:42–21:53 CET, the same machine, idle: unit 10,362 tests in
    669 files; e2e 786 ×2 (1 skipped); a11y 86; notation 121 (4 skipped); `lint:health` 0 errors,
    980 warnings.
- Result at the release gate: recorded once the run on the final commit ends.
